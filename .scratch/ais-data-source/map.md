# AIS 数据源适配与监控页面选择

Labels: wayfinder:map
Status: resolved

## Destination

按 [AIS 接入与船体展示规格](spec.md)实现后端项目适配和统一船舶数据，以及监控页面的单源选择、点和追踪长方体展示。保持来源与显示数据分离，并验证接口、连接生命周期和几何边界。

## Notes

- 用户已调用 implement 进入实现并要求提交到当前分支，实施边界以[规格](spec.md)为准。未选择的展示和控制细节按本轮已说明的默认值实施，不把这些默认值写成来源实测事实。
- 用户已确认：来源为 `ws://192.168.1.20:4323/websocket`，由后端连接并适配；项目身份、来源地址及不同项目的接入差异由后端固定，前端使用统一数据。数据源显示名称为“天津船闸 AIS”；本部署固定项目身份为 `tianjin-lock / 天津船闸`，可在后端调整。
- 用户已确认：整个监控页面一次选择一路数据源，切源时替换船舶数据；选择不按摄像头保存，切换摄像头保留页面当前的数据源。
- 用户已确认：统一船舶业务数据精简为 MMSI、时间、经纬度、船艏向、船长、船宽和速度。输入缺少 ABCD 时，根据船长宽及天线靠近船尾的假设估算尺寸分配和位置偏移；默认参数与估算边界记在[项目适配与统一船舶数据如何划分](issues/02-project-and-model.md)。估算几何与原始报告位置分离，不把假设写成实测天线位置。
- 用户已明确普通船舶、追踪船舶与视野范围的显示区分，数据源选择由当前浏览器记住并在刷新后恢复；完整显示与控制规则见[监控页面选择数据源后如何展示与恢复](issues/03-monitor-selection.md)。
- 用户提供的报文样例是本轮协议研究的一手输入；不将原始船舶报文复制进仓库。字段语义、有效值、时间与更新方式的证据集中记录在协议研究票及其研究文档。
- 当前基线为 `master` 的 `v1.1`。项目已有摄像头 PTZ、三维视场、临时点及 GeoJSON 图层，没有统一 AIS 模型、后端目标数据连接或监控页面的数据源选择。临时点是几何输入，GeoJSON 关联是摄像头维度的静态图层关系，二者均不直接作为 AIS 实时状态或页面选择的契约。
- 术语见[监控、标定与标绘术语](../../GLOSSARY.md)，源码与验证入口见 [README](../../README.md)、[API](../../docs/API.md)。现有媒体流与 AIS 目标数据是两类输入，视频来源配置保持其现有业务含义。
- 实施使用 implement、TDD 和 code-review。用户已确认在 HTTP（模拟上游 WS）与公开几何入口验证，前端执行类型检查和构建，不新增组件测试；审查基准为 `v1.1`。规范和需求两个审查分别进行，结束后提交本分支。

## Not yet specified

线上运行版本和时间基准、真实浏览器与 WebGL 性能、实际天线位置、模拟高度和现场取景精度仍需独立验收；本地代码和模拟测试不证明这些事项。

## Out of scope

- 自动持续云台控制、AIS 历史数据保存和同期回放。
- 建设供前端任意填写地址、编辑解析脚本或管理项目注册信息的通用接入平台；当前要求是由后端固定各项目的适配。
- 开发验证期间主动向真实云台下发指令或通过自动动作验证追踪。
