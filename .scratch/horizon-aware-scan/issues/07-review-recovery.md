## Question

修复 Spec 审查发现的 P2：最后一张已保存后 stop 失败，或完成状态保存前异常重启，任务会保留 failed/interrupted 与 completedCount=sampleCount；当前继续入口和界面阻止恢复，completed 来源门禁导致预扫无法进入正式扫描。

允许这些可恢复状态通过既有 start 动作仅重新执行停止与完成收尾；不得补拍、重复精确定位或放宽正式阶段的 completed 门禁。设备仍被占用时保留现有先停止要求，收尾成功后按既有逻辑自动关联识别。界面使用“确认停止并完成”说明动作，并同步相关文档。

在用户已确认的公开后端 API 边界以 TDD 覆盖：拍满后 stop 失败→手动 stop 成功→收尾→识别→可正式扫描；拍满后异常重启→收尾，不补拍或重复定位。先处理失败测试，再实现。该票集中解决本轮唯一审查发现。

## Answer

- 已移除 `start` 对已完成点数的拒绝，保留可恢复状态、设备占用与通道校验。原执行循环从 `completedCount` 开始，拍满时直接执行 stop 和完成收尾，保存 `completed` 后自动关联识别；正式扫描的来源完成门禁保持有效。
- 实时表单与截图任务页的拍满恢复按钮均显示“确认停止并完成”，README/API 已同步当前恢复行为。停止失败仍须先手动 stop 成功后才能恢复。
- 两条公开 API 回归分别在原数量门槛下复现 409，再通过最小修复转绿；覆盖停止失败、真实终止隔离线程后的异常重启、零重复定位／零补拍、自动识别及后续正式扫描。测试仅使用模拟上游和临时数据目录。
- 验证：针对回归 2/2；完整 `npm test` 104/104；`npm run build` 通过，保留已有 flv.js/Cesium 间接 CommonJS 优化提示。未进行浏览器、真实设备、截图/PTZ 严格同步或现场精度验收。
