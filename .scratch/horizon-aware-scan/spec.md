# 多点 PTZ 自动截图

Status: implemented
Integration branch: codex/ptz-waypoint-scan
Base: d7bc679

## 目标与已确认约束

用户以至少两个有序 PTZ 控制点定义自动截图路径。每个点使用设备原始 P/T/Z，相邻点之间按同一进度线性生成中间目标；执行时逐点精确定位、停稳并截图。线性变化约束目标数值，不承诺设备在两次精确定位之间按同步线性轨迹运动。

多点入口统一替换原固定 T/Z 扇区表单与“海天线预扫描→粗标定→高倍率正式扫描”专用采样流程。两点使用相同 T/Z 即可表达固定 T/Z 路径。保留独立海天线识别、人工标注、安装参数标定及已有任务、原图和标注；新任务完成后通过任务页手动创建识别。

本规格已获用户确认，作为当前实现与验收契约。操作与接口说明见 [README](../../README.md#自动截图与任务)、[API](../../docs/API.md#自动截图与任务接口)。

## 控制点与页面

- 默认显示两个待设置控制点。支持增加、删除和调整顺序，至少保留两个有效点才能开始。
- 每点可手填 P/T/Z，或显式点击“读取当前 PTZ”填入；读取失败明确显示错误，不用旧读数伪装成功。
- 点位与间隔仅作为当前摄像头的表单草稿，切换摄像头后清空并重新显示两个待设置点。不新增路径预设保存功能。
- P 输入为 0°～360°；T 为 -90°～90°有符号角，负值上抬、正值下俯；Z 保持设备原始倍率，范围为 1～该摄像头已保存的最大 Z。
- 相邻控制点不接受零 P 跨度，不支持仅改变 T/Z 而 P 不变的段。0°→360°表示一整圈；相同起止 P 与 360°→0°无效。
- 最大 P 间隔默认 5°，允许用户设置。开始前展示预计总张数，最多 10000 张；不新增全部采样点明细预览。

## 插值与截图规则

每段从 A=(Pa,Ta,Za) 到 B=(Pb,Tb,Zb)，P 始终沿递增方向变化：

1. 跨度 D=Pb-Pa；若 D<0，加 360°；要求 D>0。
2. 最大 P 间隔为 S，段数 N=ceil(D/S)，实际 P 间隔为 D/N，不超过 S。
3. 采样进度 u=i/N，i 从 0 到 N，目标为 P=(Pa+uD)%360、T=Ta+u(Tb-Ta)、Z=Za+u(Zb-Za)。
4. 每个控制点均截图，相邻两段共用的控制点只拍一次。整条路径总张数为 1+各段 N 之和；整圈首尾是两次不同进度的采样，均拍摄。
5. 总张数校验通过后才分配全部目标。控制点原始输入与实际执行的归一化目标分开保留。

示例：

- A=(10°,0°,2)、B=(20°,4°,6)，最大间隔 3°：目标依次为 (10°,0°,2)、(12.5°,1°,3)、(15°,2°,4)、(17.5°,3°,5)、(20°,4°,6)，共 5 张。
- P=350°→10°的跨度为 20°；P=10°→350°的跨度为 340°，不自动取最短路。调整点序不表示设备反向运动。
- P=0°→10°→20°、最大间隔 5°：共 5 张，连接点 10°只拍一次。
- P=0°→360°、最大间隔 5°：共 73 张；首尾物理朝向相同，但分别属于开始和完成时的采样。

最大 P 间隔定义目标密度，不保证所有倍率下画面连续覆盖。当前没有已校准的 Z→FOV 曲线，不将未知倍率的视场角作为规划依据。

## 任务生命周期与数据

- 点击开始后冻结全部逐点 PTZ 目标、控制点、最大间隔及采样标定副本；暂停后修改表单不会影响继续执行的原任务。
- 沿用精确定位、至少两次回读到位与稳定窗口、截图前后回读、设备占用、失败停止和错误暴露。多段间隔不同时，P 到位容差应对应实际采样间隔。
- 截图保存真实前后 PTZ/FOV 和采样序号，不能用控制目标覆盖真实读数；图片与 PTZ 的严格时间同步继续标记为 unverified。
- 暂停／失败／中断后手动继续，从下一个未完成目标执行；删除已完成截图不会重拍。已拍满任务只重试停止和完成收尾。
- 重启不自动移动设备，通道冲突拒绝恢复；停止失败继续占用设备直至 stop 成功。完成后保持最后位置，不自动返回起点。
- 新任务不自动创建识别；可按原任务页操作手动创建独立识别任务。

## 专用流程移除与历史兼容

移除实时表单中的采样模式、预扫倍率和 T 范围，以及识别页用于创建高倍率正式扫描的复核与启动入口；不再提供新建专用预扫和正式扫描的 API。保留独立识别、标注、参数生成及手动应用能力。

已有普通／预扫／正式扫描任务继续按原冻结计划读取和恢复，不重新规划，不删除原任务、图片和标注。历史正式扫描所需的冻结控制依据、真实 FOV 与余量检查保留在兼容路径中；历史预扫粗结果继续维持原来的应用限制。

## 实现与验证约束

沿用项目结构与依赖，不操作真实设备，不进行浏览器调试。复用现有冻结目标、截图保存与任务恢复机制，避免为新路径重建一套执行器。

按最终 API 和用户行为覆盖多段插值、跨 0°、整圈、端点去重、无效与超量输入、冻结计划、暂停／继续、重启与停止收尾，并执行必要回归和生产构建。源码、测试和构建不能替代浏览器、真实设备运动、严格同步与现场精度验收。

README、API、术语与相关索引描述当前多点截图流程；旧研究和实施票保留，不能作为新流程的实现契约。不扩展光学模型，不自动应用安装参数，不增加路径预设。
