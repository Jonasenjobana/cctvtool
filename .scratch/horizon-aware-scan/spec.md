# 海天线保持自动截图实现规格

Status: in-progress
Integration branch: feat-horizon-aware-scan
Base: ee332e4

## 目标与已确认约束

解决高倍率下固定 T 随 P 扫描导致海天线离开画面的问题。采用低倍率预扫描、人工复核海天线、粗标定预测 T、目标倍率正式扫描、最终识别拟合的流程。用户已同意低倍率预扫、预扫后人工复核、海天线居中及以下两个测试边界。

- 几何公开接口：独立椭球射线验证中心海天线与不可达目标。
- 后端任务 API：预扫、复核门禁、逐点 T、暂停续扫与最终识别衔接。

实现使用既有依赖和任务结构，不进行浏览器调试，不调用真实设备。保留原固定 T 扫描接口行为。参数不会自动写回摄像头配置。

## 几何控制

- 新增服务端公开模块 `server/horizon-control.mjs`，共用 `shared/camera-rotation.ts` 与 WGS84 零高程椭球。
- `solveHorizonTilt(calibration, { pan, referenceTilt, tiltMin, tiltMax })` 返回指定原始 P 下、允许原始 T 区间内使中心射线与椭球相切的 T。保持与参考 T 相同的俯仰分支，拒绝翻转约 180°后朝向反面的解，再选择最接近参考 T 的可达解；没有解时明确拒绝，不把越界解硬截到边界，不擅自把负值包装为 360°。
- `horizonOffsetDegrees(calibration, rawPtz)` 返回中心射线相对理论海天线的有符号角度差。使用与拟合一致的椭球缩放空间切线条件，并验证前向可见的海天线分支。
- 扫描目标以中心海天线居中为准，不要求消除画面 Roll 或让整条线水平。先验证全部计划目标存在可达 T，再开始正式扫描。
- 将粗拟合的角度残差作为预测余量的依据之一；不能直接把低倍率的 5 像素阈值当作高倍率的精度保证。保守使用 `max(0.02°, 3 × 粗拟合角度 RMS)` 作为残差余量，并要求 `abs(中心角度差) + 余量 + 到位容差 < 0.35 × 实际 VFOV`。这只是模型余量检查，不是经标定的概率置信度。
- 正式扫描的 T 到位容差为 `min(0.15°, 0.05 × VFOV)`，用于到位和截图前后检查；若视场角无效或余量不足，明确失败并保留已完成样本。沿用现有停止与设备占用规则。

## API 与任务数据

### 预扫描

现有 `POST /api/cameras/:id/snapshot-scans` 增加可选字段：

```json
{"horizon":{"preScanZoom":2,"tiltMin":0,"tiltMax":90}}
```

- 其余 `basePtz/panMin/panMax/calibration/settleMs/moveTimeoutMs` 保持现有语义。`basePtz` 为发起时实际高倍率姿态，保存其 Z 和真实 HFOV/VFOV，供恢复目标倍率与精扫计划使用。
- `preScanZoom >= 1` 且小于 `basePtz.zoom`；`0 <= tiltMin < tiltMax <= 360`，当前 T 位于该区间；界面允许填写设备实际可达范围。P 范围至少 30°，建议 90°以上。
- 预扫固定初始 T、使用低倍率；以包含两端的均匀 P 点取得至少 3 个方向，点间隔不大于 15°，不再因低倍率大 HFOV 而只取一两张。
- 每张样本保存实际低倍率 P/T/Z/FOV。固定 T 低倍预扫仍不能保证海天线全程可见；缺线或遮挡样本在复核页忽略，必要时重新预扫，不把模型候选当作真实性证明。
- 任务摘要新增可选 `horizon`：`phase: 'coarse' | 'fine'`、`targetZoom`、`tiltMin`、`tiltMax`、`targetHorizontalFov`、`targetVerticalFov`；正式阶段另记录 `sourceRecognitionTaskId/sourceRevision/sourceResultId`。保存后恢复遵循原任务控制依据。
- 摘要另有可选 `recognitionTaskId` 和 `recognitionError`。截图任务完成后自动创建识别任务并保存关联；识别创建失败要明确显示，不把已完成截图改成未完成。已有识别页保持可手动创建新识别。

### 复核后启动正式扫描

新增 `POST /api/recognition-tasks/:id/horizon-scan`：

```json
{"revision":0,"resultId":"当前拟合结果标识","reviewed":true}
```

- 来源低倍率预扫任务必须为 `completed`；识别可来自自动创建或该源任务的手动新一轮识别，不强制关联识别 ID 相等。识别状态可拟合、版本与结果标识一致、结果有效、来源图片存在、通道与安装位置/配置版本未发生冲突。未明确确认复核、旧版本或不可靠结果拒绝启动。
- 从原预扫恢复目标倍率及 P 范围，使用识别任务 `fitCamera` 与四项粗安装结果形成仅用于控制的标定副本，不应用到摄像头配置。
- 计划按目标高倍率 HFOV 等分中心点；提前求解并冻结各点的 T、控制标定和残差余量。返回普通截图任务摘要，HTTP 202。
- 逐点提交完整原始 P/T/Z，等到位停稳，检查真实 FOV 与模型余量，再按现有截图链路保存。正式扫描结束后自动创建识别任务。
- 修改后续粗标注不追溯改变已创建正式任务的控制依据；通道变更仍拒绝续扫。不要用预测姿态覆盖实际回读。

### 识别与拟合

- 复用本地识别队列与人工编辑。为海天线采样任务自动创建的识别，在识别完成后自动计算候选安装结果；失败或不可靠状态正常展示，不自动应用参数。
- `estimateInstallation` 的诊断增加 `rmsAngularResidualDegrees`，来源为参与样本真实射线的角度残差。
- 当前按完全相同 T/Z/FOV 的突变过滤不能在变 T 正式扫描上提供同等支持；沿用其适用条件并明确限制，不基于图像行位置直接比较不同 T 的样本。
- 暂停、继续、取消、重启中断、停止失败占用与删除一致性沿用现有行为。精扫的冻结目标与自动识别关联在 SQLite 中保存，不需要页面一直打开。

## 前端流程

- 自动截图区域保留普通截图，新增选择海天线预扫描的入口、预扫倍率及允许 T 范围。发起前仍重新回读当前真实 PTZ，当前倍率作为正式扫描目标倍率。
- 截图任务显示预扫/正式阶段与目标倍率，能打开自动创建的识别任务并展示识别创建失败。
- 识别页在低倍率预扫结果有效时显示明确的复核确认和“开始高倍率扫描”操作，粗标定阶段不提供应用到正式配置的按钮。复核确认绑定当前版本和结果，标注或结果改变后清除确认；存在未保存内容、识别运行中、结果失效或设备冲突时不能错误发起。
- 正式任务创建后可切到该任务查看进度。最终候选参数仍使用现有“应用到摄像头”操作。
- 不新增泛化任务编排框架、不做在线图像闭环追踪、不声称检测器能实时判断真实海天线丢失。模型预测、原始设备读数与现场观察严格区分。

## 验证与完成条件

用户已确认以上公开测试边界；按 TDD 逐个行为先失败再实现。几何测试的期望由独立射线/椭球交点生成；API 测试使用本地模拟上游和临时数据目录。完整执行 `npm test` 与 `npm run build`，保留浏览器、实际设备动作、PTZ/图片严格同步及现场精度未验收的说明。同步 README、API、术语及地图当前状态。
