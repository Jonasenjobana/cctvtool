# 海天线变倍与转向垂直偏差排查

Labels: wayfinder:map
Status: open

## Destination

明确基础倍率海天线对齐后，在变倍及调整 P/T 时出现上下错位的原因，形成有可重复证据支持的验证与最小修正方案，并定义基础倍率与随机高倍率截图联合精修的功能规格。当前工作限于研究与规格，不实施投影或标定算法修改。

## Notes

- 用户描述：基础倍率下海天线与 Cesium 理论线看起来接近，放大后的主要症状是上下错位，倾斜程度接近；偏差可能向上，也可能向下。8 倍、P 约 40～240°是本次精修工作流的示例，不作为功能固定限制或新现场采集事实。
- 用户已确认：放大期间也调整过 P 或 T。因此现象同时包含倍率和姿态变化，尚不能归因于倍率；8 倍的肉眼吻合也不等于其他姿态或倍率已通过量化验证。
- 研究票负责根因证据与受控验证；联合精修规格负责保留基础标注、使用随机高倍真实标注反推现有四项安装参数，并显示有符号垂直偏差。倍率相关光学模型仍需单独证据支持，不在该规格中自动扩展。
- 模型事实入口：[相机几何](../../src/app/camera-math.ts)、[共享旋转](../../shared/camera-rotation.ts)、[拟合](../../server/tilt-calibration.mjs)、[投影输入与光学边界](../../README.md#设备配置与参数分层)。引用的源码可能含工作区未提交改动，研究结论应注明核对时间，不把当前源码推断当作现场验证。
- 使用 wayfinder、grilling、domain-modeling；研究票使用 research。真正进入根因诊断时，依 diagnosing-bugs 先建立可重复、能检出该上下错位的反馈循环，再验证假设；本轮只设计该循环，不宣称已经复现或修复。
- 沿用本地 Markdown 跟踪：子票位于 `issues/`，`Parent:` 指向本地图，`Blocked by:` 记录依赖；`Status: open`、未分配且依赖均已解决的子票可以领取。先领取，再开展票内工作；研究答案保存在子票 `## Answer` 中，下方只登记结论摘要与链接。可实施规格按 to-spec 约定使用 `ready-for-agent` 标签。
- 研究材料保存在本目录 `research/`；研究分支只承载脱敏研究文档，按仓库规则使用 `feat-` 分支名，不提交设备原图、数据库、具体设备配置及工作区其他改动，不创建 PR 或合并研究分支。
- 遵守项目 Node 22.22.3/npm 约定；不进行浏览器调试，保留已有业务数据及无关工作区改动。

## Decisions so far

- [现有证据能否区分变倍与转向的垂直偏差](issues/01-evidence-and-observability.md)：旧资料缺少同状态返回闭环，先统一参数与残差口径，再分别验证变倍和 P/T 变化。
- [基础倍率与随机高倍率截图联合精修安装参数](issues/05-high-zoom-refinement.md)：保留基础观测，联合随机高倍标注优化现有四参数，提供原图偏差对照和严格独立复核；测试以现有识别任务 HTTP 接口集成为主，规格已标记 `ready-for-agent`。
