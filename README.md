# 云台姿态调试工具

面向通过 LiveGBS 接入的摄像头，提供设备配置、真实云台控制、姿态回读、Cesium 视场预览和截图标定样本管理。

应用由 Angular 22 前端和 Fastify 后端组成，使用 SQLite 保存设备配置与截图元数据，图片写入本地数据目录。前端通过本工具的接口操作设备，LiveGBS 登录及 token 由后端管理。

## 运行

使用 Node 22.22.3 和 npm 10.9.8，版本固定在 `.nvmrc` 与 `package.json`，依赖固定在 `package-lock.json`。Angular 的运行环境要求见[官方版本说明](https://angular.dev/reference/versions)。

```powershell
nvm use 22.22.3
npm ci
npm run dev
```

开发前端监听 `0.0.0.0:4200`，本机页面为 `http://127.0.0.1:4200`，局域网使用 `http://<本机局域网IP>:4200`；后端为 `http://127.0.0.1:3000`，前端通过同源 `/api` 代理访问后端。`npm run dev` 同时启动两者；也可分别执行 `npm run dev:api` 和 `npm run dev:web`。后台有截图任务时可单独使用 `node node_modules/@angular/cli/bin/ng.js serve --host <本机局域网IP> --port 4200` 开启局域网前端，保持后端运行。

若尚无 `.env`，将 `.env.example` 复制为 `.env` 并填写 `LIVEGBS_URL`、`LIVEGBS_USERNAME`、`LIVEGBS_PASSWORD`。密码填写登录接口要求的参数值，后端原样传递；认证信息保留在本地 `.env` 中，文件已忽略提交。

| 配置 | 默认值或用途 |
| --- | --- |
| `HOST`、`PORT` | 后端监听地址与端口，默认 `127.0.0.1:3000`；修改开发端口时同步 `proxy.conf.json` |
| `LIVEGBS_TIMEOUT_MS` | 每次上游请求超时，默认 15000 毫秒 |
| `LIVEGBS_SMS_ID` | 视频流媒体节点编号，默认 `34020000002020000001`；CMS 主机与端口取 `LIVEGBS_URL` |
| `DATA_DIR` | 数据目录，默认项目下 `data/`，相对路径以项目根目录解析 |
| `ESSLD_PYTHON`、`ESSLD_UPSTREAM` | 本地识别使用的 Python 和 ESSLD 源码目录，默认 `data/essld/.venv/Scripts/python.exe` 与 `data/essld/upstream`，相对路径以项目根目录解析 |
| `MCP_HOST`、`MCP_PORT` | 独立 MCP HTTP 服务，默认监听 `0.0.0.0:3001` |
| `MCP_API_KEY` | 必填的 MCP 访问密钥，客户端通过 `Authorization: Bearer` 传入 |
| `MCP_ALLOWED_HOSTS`、`MCP_ALLOWED_ORIGINS` | 可选的额外服务主机名及浏览器来源，配置见 [MCP 使用说明](docs/MCP使用说明.md) |

生产运行及检查：

```powershell
npm run build
npm start
npm test
```

生产入口为 `http://127.0.0.1:3000`，Fastify 同时提供页面、Cesium 静态资源、业务接口与截图文件。数据库位于 `data/cctv.sqlite`，图片位于 `data/snapshots/`；备份时保留完整数据目录。

## 首版范围

1. 注册、编辑和选择摄像头，将设备标识、安装位置、P 轴姿态、P/T 偏移和画面 Roll 修正保存到 SQLite。
2. 控制当前摄像头上、下、左、右及变倍，并定时回读真实 PTZ。
3. 根据安装位置、P 轴姿态、P/T 偏移、画面 Roll 修正、真实 PTZ 和接口视场角，在 Cesium 显示摄像头位置、朝向、视锥及可计算的地表覆盖范围。
4. 提供最佳观察、跟随摄像头和固定观察，支持修改安装标定参数后即时对照。
5. 获取快照，将图片、姿态和采样时使用的标定参数一起保存；支持固定 T/Z 的 P 扇区采样，以及低倍率预扫描、人工复核、粗标定预测 T 的高倍率正式扫描；提供任务分组、进度、暂停／继续、历史回看、单图删除及任务全景拼接。
6. 直接解析拼接的 WS-FLV 直播，在 Cesium 视锥内显示随真实 PTZ 与安装参数变化的视频截面。
7. 通过 MCP 按摄像头和时间段读取截图，由连接端 AI 标注海天线，生成可复核的 P 轴倾斜数据。
8. 从截图任务创建本地 ESSLD 识别任务，在页面复核和编辑海天线、忽略异常图片，联合生成 P 轴前后倾、左右倾、T 偏移和画面 Roll 修正，并手动应用最终结果到该摄像头配置。

参考项目中的保护区、鱼圈、AIS 和识别框属于原业务，不纳入本工具首版。海天线可由网页调用本地 ESSLD 后人工复核，也可由连接 MCP 的视觉 AI 标注；数值拟合由本工具完成。

## 页面布局

- 左侧菜单：固定 56 像素宽的图标栏，提供三维视场、设备、截图记录、截图任务和识别任务图标；设备和截图图标展开对应侧栏，任务图标进入对应页面。识别页使用完整工作区，隐藏实时云台表单；宽屏分为左侧任务列表、中间截图复核与横向缩略图、右侧安装参数，三部分分别滚动。窄屏将安装参数排在复核区下方，小屏将任务列表改为顶部横向排列。
- 中间 Cesium：高德卫星底图上展示摄像头、视场与直播视频截面，提供最佳观察、跟随／固定观察；历史快照在原直播截面的位置显示截图。下方保留直播状态、重连、不透明度控制；实时模式提供最新截图预览，历史模式显示采样时间、尺寸、PTZ、原图入口及截图不透明度。工具栏“直播融合”按钮开启／关闭视频纹理及媒体连接。
- 最右侧容器：顶部固定云台控制区，方向键按上／下／左／右排列，中间留空，加减键位于下方，截图按钮位于方向控件旁边。方向和变倍按钮按住控制、松手停止，下方提供速度及独立“停止”按钮；“精确 PTZ（高级）”默认折叠，展开后手动输入 P/T/Z 并提交。控件下方显示只读的 PTZ、视场角及回读时间。
- 安装表单顺着控制区向下排列，可滚动编辑 P 轴前后倾、左右倾、默认朝向（P 偏移）、经度、纬度、高度和设备标识；“高级标定”中编辑 T 偏移与画面 Roll 修正，默认均为 0。底部提供保存按钮，错误及保存状态在对应操作附近显示。
- 实时画面右侧表单的“自动截图”选择普通截图或海天线预扫描，填写最小／最大 P；预扫还需填写低倍率及设备允许的原始 T 范围。开始时重新回读当前 PTZ，普通模式固定当时的 T/Z，预扫保存当时的 Z 和真实视场角供后续正式扫描使用。截图任务页显示阶段、目标倍率、状态和关联识别入口，提供暂停、继续和取消；复核后的正式扫描从识别页发起。
- 截图记录按一次接口调用分组；自动扫描每组包含多张，手动截图与旧记录各自作为单张组。分组和组内图片均分页加载，默认折叠。截图记录及任务详情中的图片支持右键“删除截图”，删除当前历史图后退出该图预览；正在扫描的设备需先暂停或停止再删除。

“云台 P 轴姿态”、T 偏移与画面 Roll 修正旁提供圆形问号。鼠标悬浮、键盘聚焦或点击问号可查看对应手绘说明图，移动到图上可继续阅读；移开并离开焦点、按 Escape 或点击外部可关闭。浮层位于浏览器顶层，避免被表单滚动区域裁切。

插图以现场的白色鹅颈支架、灰色上壳和黑色悬挂式云台为外形参考，分别说明整根 P 轴的安装倾斜、T 读数与实际俯仰的固定偏差，以及绕最终光轴的画面 Roll。说明强调参数用于对齐三维模型与实拍海天线，不下发移动指令。三张 PNG 随应用部署，使用内置 image_gen 生成，维护提示词见[生成提示词](docs/calibration-help-prompts.json)。

## 底图与坐标

底图使用高德卫星影像 `https://webst0{s}.is.autonavi.com/appmaptile?style=6&x={x}&y={y}&z={z}`，子域名为 1～4，最高瓦片级别为 18。

高德使用 [GCJ-02 坐标系](https://lbs.amap.com/faq/advisory/others/39838)。本项目沿用参考场景的本地近似转换，仅在影像层进行底图偏移：选取瓦片时将 WGS84 转为 GCJ-02，计算瓦片地理边界时将 GCJ-02 逆算回 WGS84，瓦片原生 WebMercator 网格保持原样。适配通过独立的 `AmapTilingScheme` 和 `AmapProjection` 实现。

摄像头位置、视锥、海面交点及数据库中的安装参数统一保持 WGS84。转换适用范围外保持原坐标；实际地物对齐和现场精度仍需验收。

## 实时视频

采用参考 Cesium 场景 `core/player.ts` 的媒体链路，使用固定版本 `flv.js 1.6.2` 直接[解析 FLV over WebSocket](https://github.com/bilibili/flv.js/blob/master/docs/livestream.md)。FLV 解复用并转封装为 MediaSource 数据后，由浏览器将 H.264 视频解码到原生 `HTMLVideoElement`，Cesium 直接使用该元素作为视频纹理，整个过程只建立一条媒体连接。

```text
WS-FLV → flv.js → MediaSource / video → Cesium 视频纹理截面
```

视频截面位于摄像头前方 500 米，四角按同一安装姿态、P/T 和接口 HFOV/VFOV 计算，与视锥端面一致；旋转 P、T 或编辑安装参数时同步更新，不跟随地图观察相机转动。保持完整视频比例，与 FOV 比例不同时透明留边。状态栏可调视频不透明度，方便与底图对照；最佳观察沿用约 65% 的视口占比。

截面显示关闭深度测试，避免低位摄像头的视频画面穿入近似海面后被裁掉；是否位于地球背面按摄像头位置判断。该截面用于视角对照，不表示视频已经贴合地形或通过了地物标定。

后端 `GET /api/playback?cameraId=<本地摄像头ID>` 根据 CMS 配置和该设备保存的 `serial/code` 拼接地址。未传 `cameraId` 时使用默认设备：

- `serial = 34020000001320000088`
- `code = 34020000001320000001`
- `sms_id` 默认 `34020000002020000001`，可通过 `LIVEGBS_SMS_ID` 修改。

```text
ws[s]://{cms_ip}:{cms_http[s]_port}/sms/{sms_id}/ws-flv/hls/{serial}_{code}.flv
```

CMS 主机、端口与 HTTP／HTTPS 协议取 `LIVEGBS_URL`，分别映射为 `ws`／`wss`。默认设备的地址示例为：

```text
ws://192.168.1.15:10000/sms/34020000002020000001/ws-flv/hls/34020000001320000088_34020000001320000001.flv
```

直播采用当前摄像头已保存的 serial/code；只有表单中的通道标识也与直播源一致，且存在有效位置、姿态和接口视场角时，才显示视频截面。切换摄像头时取消旧地址请求，清空媒体源及纹理引用，由媒体组件销毁旧 MediaSource 与 WebSocket，再取得新设备地址并连接；旧 HTTP 响应不能覆盖新设备。注册新设备时停止当前直播；保存设备或通道编号后重新取流，只修改安装参数时保持现有媒体连接。

进入历史记录时将直播替换为该条记录的截图，使用采样时的安装参数、PTZ 和视场角放置在同一截面，按原图宽高比透明留边。历史图片来自对应记录的原图地址。

浏览器直接建立媒体 WebSocket，不请求取流地址接口，也不拼接登录 token；PTZ、控制和截图 API 的认证仍由后端处理。HTTPS 页面需将 CMS 配置为其可用的 HTTPS 地址及端口，以生成 WSS 地址。

媒体默认静音自动播放，新解码帧触发 Cesium 显式绘制，不重复拉流。关闭融合、进入历史快照或组件销毁时，撤掉视频纹理、帧回调、MediaSource 及 WebSocket；重连先释放旧连接，再建立新连接。分辨率变化时重新创建纹理，避免沿用旧尺寸。播放或纹理上传失败时明确显示错误，可重新连接；纹理失败不停止底图与云台界面。截图继续使用右侧截图按钮，经后端保存图片地址、PTZ 及安装参数。

播放依赖浏览器 MediaSource 和当前 H.264 编码支持；其他视频编码不作兼容承诺。浏览器实际解码、WebGL 纹理上传与地物对齐仍需现场验收。

## 设备配置与参数分层

| 分类 | 内容 | 约定 |
| --- | --- | --- |
| 设备标识 | 本地 ID、名称、LiveGBS `serial`、通道编号 `code` | `serial`、`code` 均按字符串保存；本地 ID 不绑定第三方编号 |
| 安装位置 | 经度、纬度、高度 | 经纬度统一为 WGS84，高度单位米，采用 WGS84 椭球高程；海域以零高程近似海面，其他高程基准须在填写前换算。位置可留空完成注册，填写完整后才生成投影 |
| P 轴姿态 | 前后倾、左右倾 | 描述 P 轴的安装倾斜，角度以度保存到数据库，运行时生成旋转矩阵 |
| 默认朝向 | 安装坐标系的基准方位（P 偏移） | 角度以度保存到数据库，先旋转整个底座的安装朝向，再应用该安装坐标系中的前后倾、左右倾 |
| T 偏移 | 局部 T 零位修正 | `tiltOffset`，单位度，正值上抬；局部俯仰旋转为 `Rx(tiltOffset - Tilt)` |
| 画面 Roll 修正 | 绕最终光轴的固定旋转 | `imageRoll`，单位度，在局部 P/T 之后应用 `Ry(imageRoll)`；单通道不区分主副镜头 |
| 实时视场角 | HFOV = `HorizontalFieldAngle`，VFOV = `VerticalFieldAngle` | 直接使用 LiveGBS PTZ 接口返回值，作为三维投影的唯一视场角来源，与同次回读的 P／T／Z 一起更新 |
| 实时状态 | 原始 PTZ 响应、归一后的 P／T／Z、采样时间、请求状态 | 与数据库中的安装参数、控制目标及页面格式分开保存 |

通道配置以 `code` 为主；快照接口也支持通道序号 `channel`，它与 `code` 是两种标识，不能相互当作编号使用。若采用 `channel`，需明确其与当前设备通道的对应关系。

朝向采用真北 0°、向东 90°约定。当前适配按 P／T／视场角为度、P 顺时针和正 T 向下处理，真实控制方向与设备边界仍需现场确认。默认朝向作为安装方位旋转整个底座，前后倾和左右倾在该安装坐标系下定义，再绕此固定 P 轴应用设备回读 P。视锥及其他投影使用同一结果，原始 PTZ 和真实控制目标保持设备读数语义。

共用旋转链为 `Rz(-panOffset) × Rx(pAxisPitch) × Ry(pAxisRoll) × Rz(-Pan) × Rx(tiltOffset - Tilt) × Ry(imageRoll)`，再由当地 ENU 转到世界坐标。前三项生成固定安装矩阵，与参考场景 `createInstallationRotation()` 的 Z-X-Y 约定一致；默认朝向只在安装矩阵中应用一次。P 轴安装、T 零位及画面 Roll 的旋转次序固定。已有数据库启动时补齐 `tiltOffset/imageRoll` 两列并初始化为 0；历史截图缺少两项时按当时的零修正读取，不改写原始截图元数据。

与参考算法对照时，使用相同的安装位置、姿态、PTZ 和 HFOV/VFOV；本工具采用图像中心主点、零额外镜头 P/T 修正及零光心位移。参考项目的倍率表、主点偏移和镜头位移属于独立光学输入，对照时须统一这些输入。参考数值回归由参考原函数生成夹具，运行测试不依赖本机外部参考目录。

变倍范围和控制速度按设备能力确定，图像尺寸取实际快照。Zoom 用于变倍控制与读数展示。缺少有效位置、姿态或接口视场角时，明确显示缺项，当前实时投影不可用。

## 表单保存

1. 进入调试页或切换设备时，从后端加载该通道在 SQLite 中保存的安装参数。
2. 修改 P 轴前后倾、左右倾、P/T 偏移、画面 Roll 修正、经纬度或高度时，使用表单草稿即时预览；修改这些参数不下发云台指令。
3. 点击“保存”后，由后端校验并将当前通道的这些字段作为一次完整更新写入数据库，成功后以返回的数据库记录更新已保存状态。保存失败时保留草稿并显示错误，不提示保存成功。
4. SQLite 中的记录是已保存配置的唯一来源；刷新页面、切换设备后重新进入或重启服务时均可恢复。数据库保存角度及位置原值，旋转矩阵在运行时派生。

## 调试流程

### 姿态回读与控制

1. 选择摄像头后每 1000 毫秒轮询其真实 PTZ，显示最新读数、回读时间与本次请求耗时。
2. 同一设备的回读请求不重叠。切换设备或离开调试页时停止旧轮询，旧响应不能覆盖新设备状态。
3. 方向和变倍按钮按下时调用 `/api/v1/control/ptz`，分别发送 `up/down/left/right/zoomin/zoomout`；松手发送 `stop`。控制速度为 0～255 整数，默认 129，不需要先回读或计算相对角度。鼠标移出、触摸移出或取消、键盘松开、窗口失焦和页面隐藏也结束当前按住；键盘 Space／Enter 按住可控制，重复按键不重复发送启动。离开页面时使用 keepalive 请求发送停止。
4. 每次按住绑定启动时的设备。松手立即请求停止；启动请求仍在途时，后端将停止排在该请求之后，前端在启动结束后补发一次停止，处理快速点击和回包迟到。启动失败也尝试停止；停止失败显示错误并保留控制锁，可点击“停止”重试。服务正常关闭时会尝试停止尚未结束的连续控制。
5. “精确 PTZ（高级）”点击展开后提供独立 P/T/Z 表单，填写数值或主动点击“填入当前读数”，点击“发送精确定位”才调用 `ptzprecise`。请求使用设备原始参数语义，P/T 范围为 0～360°、Z 最小为 1，具体设备范围及上限以现场为准。安装修正不叠加到任何控制请求中。
6. 控制请求目标和设备回读分开显示；请求接受不代表设备已到位或已停稳。连续控制、精确定位及停止期间保持 PTZ 回读，截图期间暂停轮询。回读失败时保留最近读数并标记过期；连续方向控制及停止不依赖旧 PTZ 值。
7. 同一通道的连续控制、精确定位、截图和配置保存互斥；连续控制的锁保持到 stop 成功。停止请求可在启动请求仍在途时接收，不因控制锁返回 409。停止失败时仍可重试停止。

### Cesium 视场与最佳观察

- 使用安装位置、P 轴姿态、P/T 偏移和画面 Roll 修正生成位置、方向及上向量，结合接口视场角生成视场；修改安装参数只重算模型，不改写设备 PTZ。
- 最佳观察参考 `focusVideo()`：主相机置于配置的安装位置并沿当前成像方向观察，结合容器宽高比扩大观察视场，参考占比约为视口的 65%。观察视场的调整不能反写接口回读的 HFOV／VFOV。
- 跟随观察在当前设备有效姿态或视场角变化时更新主视点；固定观察保留主视点，继续更新视锥。切回跟随或点击最佳观察时重新对准。
- PTZ 及视场角相同时不重复创建视锥、实体或 Viewer；窗口尺寸变化时同步视口与观察参数，退出页面释放自身资源。
- 地面覆盖线采用 WGS84 椭球零高程近似海面，只显示前向 10 公里以内的有效交点。当前未接入地形高程，不能据此认定陆地遮挡与覆盖范围准确。

### 截图与样本保存

截图流程为“设备停稳 → 回读 PTZ → 请求实时快照 → 再次回读 PTZ → 保存图片及样本”。截图期间避免继续发送本工具的控制指令；前后回读用于发现姿态变化，不能证明图片与 PTZ 严格同步。

每条样本至少保存：

- 设备本地 ID、当时的名称及 `serial`／通道标识。
- 原始图片文件、实际宽高、格式及后端生成的访问地址。
- 快照请求开始／结束时间、前后 PTZ 原始值与回读时间；响应提供 `Channel-Snap-Time` 时保留原值。
- 采样时接口回读的 HFOV／VFOV，以及实际用于该样本的经纬度、高度、P 轴前后倾、左右倾、P/T 偏移和画面 Roll 修正副本，避免后续改配置后无法还原样本；表单尚未保存时标明样本使用草稿参数。
- 姿态是否变化、是否采用表单草稿和时间对应尚未验证的状态。

`channelsnap` 已实测返回图片二进制，由后端保存后生成本工具的访问地址。图片保存与元数据写入都成功才返回成功；失败时清理本次产生的文件或记录，避免留下不可访问的样本。

历史回看采用采样时的参数与姿态，截图显示在中间 Cesium 原 CCTV 直播截面的位置，可调截图不透明度并打开原图。历史数据明确标记，安装表单及云台控制只读；切换记录时清除上一张画面，图片加载失败显示错误；点击“返回实时”清除历史纹理，恢复当前草稿、最新回读及直播开关状态。设备配置变更不修改已保存样本。

### 自动扇区截图与任务

在实时右侧表单选择“普通截图（固定 T/Z）”，先调整好画面，填写设备原始 P 的最小／最大值，再点击“开始自动截图”。后端从当前倍率的真实水平视场角计算张数 `ceil((最大 P - 最小 P) / HFOV)`，将区间等分后取每段中心。例如 0°～150°、HFOV 30°时，依次到达 15°、45°、75°、105°、135°并保存 5 张。P 限制作用于镜头中心的目标值，单张画面可能覆盖区间边缘以外；不支持跨 0°的区间，单次最多 10000 张。

普通模式每个采样点通过精确 PTZ 提交完整目标，仅改变 P，T/Z 使用任务开始时的当前读数。至少连续两次回读到位，并满足默认 1000 毫秒的稳定窗口后抓图，再次回读确认未变化才保存；定位默认等待 30000 毫秒，失败时终止并保留已保存图片。图片与 PTZ 的严格同步仍为 `unverified`。

海天线两阶段采样按以下流程操作：

1. 先人工调好 T，确认预扫低倍率下海天线可见，再恢复所需的正式目标倍率。在“海天线预扫描”填写更低的预扫倍率、P 范围和设备实际可达的原始 T 范围。P 覆盖至少 30°，建议 90°以上；当前 T 必须在允许范围内。表单默认 T 0°～360°仅为接口取值范围，不表示设备具有该机械能力。
2. 点击“开始海天线预扫描”，页面重新回读当前真实 PTZ，保存高倍率 Z 与 HFOV/VFOV；预扫使用低倍率和固定初始 T，按包含两端、间隔不超过 15°的均匀 P 点采样，至少三个方向。固定 T 预扫仍可能缺线或遮挡，应在识别页忽略这些图片，必要时重新预扫。
3. 预扫完成后自动创建本地识别任务，识别结束后自动生成粗标定候选；任务页可打开关联识别。自动创建识别失败时显示原因，已完成截图保留，可手动创建识别任务。逐张复核海天线，编辑或忽略异常图片后保存并重新生成；只有结果有效、无未保存标注且源预扫已完成，才能勾选“我已复核当前结果使用的全部海天线标注”。确认绑定当前任务、标注版本和结果，修改或重新生成后需再次确认。
4. 点击“开始高倍率扫描”，后端校验版本、来源图片、设备通道、配置与占用状态，使用粗标定副本预测各方向 T。全部目标可达并满足预测余量才创建正式任务；不可达或余量不足会明确失败，不将越界 T 截到边界。正式计划、控制标定和粗结果引用均被冻结，后续修改粗标注不改变已创建计划；页面转到该截图任务查看进度。
5. 正式扫描恢复目标倍率，逐点控制 P/T/Z，以真实回读检查到位、实际视场角及模型余量，保存真实 PTZ，结束后自动创建最终识别及候选结果。逐图复核、重新生成后，仍通过“应用到摄像头”手动保存最终四项安装参数。预扫页的粗结果仅供正式扫描控制，不写入设备配置。

海天线居中指图像横向中部接近画面中心，不要求整条线水平。预测依赖已复核样本和安装模型，低倍率拟合通过像素门槛不代表高倍率精度已验收；这不是在线图像闭环，不会实时判断真实海天线是否丢失。几何与余量约束见 [API](docs/API.md#海天线预扫描与正式扫描接口)。

启动接口立即返回 HTTP 202、任务／分组 ID、计算出的张数和步长。任务与每张图片的真实 PTZ、采样序号及安装参数副本持久化到 SQLite。暂停会等待在途精确定位或抓图返回后发送 stop，确认停止后释放设备占用；继续从下一个未完成采样点执行，沿用任务原采样计划、视场角和标定副本，正式阶段使用已冻结的逐点 T。结束、失败、取消及服务正常关闭均尝试停止云台；停止失败保留设备占用，可用右侧“停止”重试。完成后保持最后采样方向，不自动回到起点。

后台任务不依赖网页保持打开。任务页显示已采样数、计划总数和现存图片数；删除截图只减少现存图片数，继续时不会重拍用户已删除的完成点。正常关闭会取消执行中的任务；异常重启后标记为“已中断”，暂停状态保持，均不会自动转动设备。暂停、失败及中断的任务可手动继续；已拍满时显示“确认停止并完成”，仅重试停止与完成收尾，不重复定位或抓图。停止失败占用设备时须先用“停止”重试成功；海天线任务收尾完成后自动关联识别，正式扫描仍要求来源预扫为已完成。通道标识改变后拒绝继续旧任务。同一个数据目录只运行一个业务后端，独立的只读 MCP 可同时运行。接口与调用示例见 [API](docs/API.md#自动扇区截图与任务接口)。

任务详情的“任务截图”旁提供“生成全景图”按钮。任务暂停或结束后，至少有两张图片即可生成；会自动翻页读取本任务全部现存截图，按采样顺序处理。使用每张截图保存的安装姿态、P/T、T 偏移、画面 Roll 及 HFOV/VFOV，沿用共享旋转模型将画面投影到同一水平圆柱面，重叠区域按边缘权重融合。安装经纬度和高度不参与这一远景旋转拼接。

生成过程显示进度并可取消，图片逐张解码和释放；结果支持横向滚动查看及下载 PNG。浏览器内计算，原图和数据库记录保持原样。画布最多 16384×4096，总像素不超过 1600 万，长任务按比例缩小；删除图片、继续采样、切换任务或离开任务页时清除旧预览及释放资源。截图读取失败或生成期间记录发生变化时明确报错，刷新后重试。已删除或未拍摄的中间视野保持透明，运动目标、近景视差、缺少重叠及标定误差仍可能产生接缝；画面包含竖直方向时不支持水平圆柱全景。

### 海天线与辅助标定

本工具提供只读 Streamable HTTP MCP，默认监听独立的 `0.0.0.0:3001`，供局域网内其他 MCP 客户端连接。MCP 读取已存在的 SQLite 数据库和截图文件，将原图以 MCP 图片内容返回，由连接端具备视觉能力的 AI 识别海天线，再调用数值工具生成 P 轴前后倾、左右倾。MCP 不调用外部模型，也不下发设备控制或改写摄像头配置。

配置 `.env` 的 `MCP_API_KEY` 后，在服务端运行 `npm run mcp`。当前局域网地址为 `http://10.10.101.132:3001/mcp`，客户端配置示例见 [mcp.config.example.json](mcp.config.example.json)：

```json
{
  "mcpServers": {
    "cctv-tilt-calibration": {
      "url": "http://10.10.101.132:3001/mcp",
      "headers": {
        "Authorization": "Bearer <MCP_API_KEY>"
      }
    }
  }
}
```

MCP 与网页应用共用 `.env` 中 `DATA_DIR` 指向的数据目录，先通过网页注册设备并保存截图。HTTP 服务按请求创建只读 MCP 实例，无需会话 ID，支持多个客户端；认证、Host/Origin 校验及协议处理使用独立服务入口。当前本机的实际客户端连接配置保存在忽略提交的 `mcp.config.local.json` 中。完整启动、参数、直接 HTTP 调用和排错见 [MCP 使用说明](docs/MCP使用说明.md)。本机 stdio 入口仍可通过 `npm run --silent mcp:stdio` 使用。

| 工具 | 用途 |
| --- | --- |
| `list_cameras` | 列出摄像头、当前安装参数、截图数量和可用时间范围 |
| `query_snapshots` | 按 `cameraId/startTime/endTime` 查询截图，可用 `groupId` 限定一次任务，支持分页；开始包含、结束不包含 |
| `get_snapshot` | 返回原图图片内容与采样 PTZ、FOV、尺寸和时间，供 AI 看图 |
| `estimate_p_axis_tilt` | 接收截图 ID 和海天线归一化点，从数据库读取采样参数并拟合倾斜 |

操作流程：

1. 确定摄像头和时间段；起止时间须带时区，例如 `2026-11-09T11:00:00+08:00`。筛选依据为本工具的 `createdAt`，不使用无时区的快照响应头时间。
2. AI 读取原图，识别远处海天线，每张图至少标注两个点。`x = 像素横坐标 / 图片宽度`、`y = 像素纵坐标 / 图片高度`，左上角为原点，数值均为 0～1；点的横向跨度至少为图宽的 10%。看不清、遮挡或只有岸线时跳过，不能补造点位。
3. 至少选择 3 张停稳截图、3 个不同 P 方向，方向覆盖至少 30°，建议 90°以上。工具排除 `poseChanged`、无效 PTZ/FOV 或设备通道不一致的样本。
4. MCP 拟合固定当前保存的经纬度、高度、P/T 偏移和画面 Roll 修正，使用采样时的真实 P/T 与接口 FOV，考虑 WGS84 椭球海平线的曲率影响。前端投影和拟合共用局部旋转模型。此 MCP 流程只估计 P 轴前后倾、左右倾，T 偏移与画面 Roll 需先复核保存。
5. 返回 `pAxisPitch`、`pAxisRoll`、总倾角、轴方向以及逐图残差。结果和标注仅通过 MCP 返回，不写回数据库或生成持久化报告文件；用户复核后在现有表单填写两个角度并保存。

只有 `status=estimated` 才返回安装角度；样本不足返回 `insufficient_data`，未收敛、不可辨识或均方根残差超过 5 像素返回 `unreliable`，后二者的 `installation` 为 `null`。即使通过拟合，结果也属于待复核估计，不能认定现场标定已经完成。

当前模型 `wgs84-horizon-p-axis-v3` 假定固定安装、P 轴朝上，前后倾和左右倾均在 -89°～89°内，并以默认朝向定义的安装坐标系为参考；T 偏移和画面 Roll 使用已保存值，主点位于图像中心，海面近似椭球零高程。T 偏移或画面 Roll 设置不准会影响 P 轴结果，本次不联合求解这两项。标定结果应与其输出的模型编号及安装旋转约定一起复核；更新拟合实现后，需重新连接 MCP 进程以载入当前模型。高度、绝对朝向、潮汐、折射、畸变和稳像裁剪未由海天线求解。详细参数及输出见[接口文档](docs/API.md#截图标定-mcp)。

## 本地模型识别与安装参数

该流程在网页完成，不需要 MCP。Python 环境与权重的安装步骤见 [ESSLD 环境说明](docs/MCP使用说明.md#essld-独立离线试跑)，Python 3.11 与依赖独立于 Node/npm。默认使用本机已经安装的 `data/essld/.venv/` 和 `data/essld/upstream/`；环境或源码移动后通过 `ESSLD_PYTHON`、`ESSLD_UPSTREAM` 指定。识别环境缺失或执行失败会明确显示错误。

1. 海天线预扫描和正式扫描完成后自动创建识别，截图任务页可打开关联任务。也可选择已暂停或已结束且有图片的任务，点击“创建识别任务”。识别使用创建时的现存截图集合；后续采集新图需要创建新一轮识别。
2. 在“识别任务”查看进度。本地 CPU 模型任务依次执行，支持取消；海天线采样自动创建的识别完成后自动生成候选安装结果，不自动应用参数。服务关闭或异常重启后保留已处理数据并标为中断，可从原截图任务创建新一轮识别。
3. 逐张复核原图上的线：橙色虚线为模型原始结果，红色实线为当前标注。拖动两端或输入 0～1 归一化坐标，横向跨度至少 10%；“重新画线”提供初始线，再根据原图调整。坐标和忽略状态可保存，切换任务、图片或菜单页面时先保存当前修改；保存失败则保留草稿并停止切换。
4. 可勾选“忽略此图”或恢复参与计算。模型未给出合法线、截图前后姿态变化时默认忽略；同一 T/Z/FOV 的附近最多 6 张图作为参照，至少 3 张参照时比较倾角及归一化高度的中位数与 MAD，门槛为 `max(3° 或图高 5%, 3 × 1.4826 × MAD)`，突变图默认忽略。正式扫描逐点 T 不同，该过滤不直接比较不同 T 的图像行位置，不能提供与固定 T 扫描相同的突变过滤支持。连续的岸线误识别仍需人工处理；自动忽略项可以人工重标并恢复。
5. 点击“生成安装参数”，使用全部未忽略、源记录仍存在的图片及实际 PTZ/FOV，联合求解 `pAxisPitch/pAxisRoll/tiltOffset/imageRoll`。至少需要 3 张停稳图、3 个 P 方向、覆盖 30°，建议 90°以上；固定 T/Z 的扫描可参与计算。固定经纬度、高度和默认朝向，两个 P 轴倾角限制在 -89°～89°，T/Roll 在 -180°～180°。只有收敛、四参数可辨识且均方根残差不超过 5 像素时，页面展示可应用参数。
6. 普通或正式扫描的识别结果复核后点击“应用到摄像头”，仅保存四项安装修正，立即同步当前设备表单及三维投影；不发送 PTZ 控制、不修改原始读数或历史截图。预扫结果用于复核后启动高倍率正式扫描。标注变化会清除旧结果；配置变化、参与样本被删除、旧版本或重复应用均返回冲突，需按提示重新生成。

本地联合拟合模型为 `wgs84-horizon-installation-v1`；MCP 保持只估计两个 P 轴倾角的 `wgs84-horizon-p-axis-v3`。任务、模型原始标注、人工标注、忽略状态及计算结果均保存到 SQLite，重启后可继续复核。源截图被删除时识别任务保留标注记录，并在重新生成时排除该图。

通过数值检查不等于现场标定准确。山体、岸线、船体或近处海水上的错误线可能形成平稳序列；模型结果必须复核。高度、默认朝向、潮汐、折射、畸变、稳像裁剪以及截图/PTZ 严格同步均未由这四个参数解决。

## 前后端与存储职责

```text
Angular 页面 → Fastify → LiveGBS
                  ├─ SQLite：设备配置、标定参数、截图元数据、识别任务与标注
                  ├─ 本地 Python / ESSLD：识别海天线候选
                  └─ 本地数据目录：原始截图文件
```

- 前端负责操作表单、交互状态、WS-FLV 解复用与浏览器解码、Cesium 视频纹理展示及展示边界的数据格式化。
- Fastify 负责 LiveGBS 认证、PTZ 回读与控制适配、快照转存和配置／样本持久化。LiveGBS 地址与凭据由后端配置，登录 token 由后端管理。
- token 缓存在后端内存中，并发请求共用登录；临近过期重新登录，上游返回 401 时重新登录并重试一次。网络故障和超时不自动重发控制指令。
- LiveGBS 原始响应与工具内部的业务数据分别处理，字段归一在接入边界完成；接口不返回表单专用的拼接文本。
- SQLite 按注册通道保存设备标识、经纬度、椭球高度、P 轴前后倾、左右倾、P/T 偏移和画面 Roll 修正，并保存截图元数据；截图文件存于后端数据目录，文件名由后端生成。两者共同组成持久化数据。
- 登录失败、回读失败、控制失败和保存失败分别暴露；不得用旧值伪装成功。

## 技术栈

- 前端：Angular 22.2.5 + Cesium 1.147.0。
- 后端：Fastify 5.12.8 + Node 内置 `node:sqlite`。

Node 22 中 `node:sqlite` 会输出实验性功能提示，数据库读写及重启恢复由接口回归验证。参考项目旧 Angular 11 代码仅用于理解行为，本工具独立运行。

## 联调与验收

本工具前后端契约和上游实测结构见[接口文档](docs/API.md)，现场仍需确认[待确认项](docs/API.md#联调前待确认)。自动检查使用本地模拟 LiveGBS 验证并发登录、401 重试、错误暴露、保存互斥、重启恢复与截图失败清理；几何回归覆盖倾斜 P 轴、P 偏移、接口视场角、最佳观察及视频截面的四角和比例；媒体生命周期回归使用模拟解码器检查单连接、重连释放、错误与迟到事件，并验证新帧绘制及取消；播放配置回归覆盖默认通道、按摄像头切换、WS／WSS 和地址中的认证数据隔离；底图回归覆盖坐标往返、GCJ-02 选片、WGS84 瓦片边界与标准投影隔离；标定回归以独立射线生成的合成海天线验证倾斜恢复，并通过真实 stdio 协议检查查询、读图和计算。

首版验收至少覆盖：

1. 表单中的 P 轴姿态、P/T 偏移、画面 Roll 修正、经纬度和高度可写入 SQLite，刷新或重启后读数一致；不同通道的参数互不污染，保存失败可见且草稿保留。
2. 按住方向或变倍后设备连续运动，松手后收到停止指令；精确定位仅由高级表单提交。回读更新时，Cesium 使用同次 PTZ 与视场角显示；发送失败、停止失败与未到位可区分。
3. 切换设备时旧轮询与请求不串入新设备；网络故障有明确状态，恢复后可以继续读取。
4. 最佳观察、固定观察与参数编辑分别生效；缺少有效参数时显示缺项。
5. 截图及采样信息可保存并在重启后回看，参数副本保持采样时的值；图片或数据库写入失败不会显示成功。
