# 云台姿态调试工具

面向通过 LiveGBS 接入的摄像头，提供设备配置、真实云台控制、姿态回读、Cesium 视场预览和截图标定样本管理。

应用由 Angular 22 前端和 Fastify 后端组成，使用 SQLite 保存设备配置与截图元数据，图片写入本地数据目录。前端通过本工具的接口操作设备，LiveGBS 登录及 token 由后端管理。

## 运行

使用 Node 22.22.3 和 npm 10.9.8，版本固定在 `.nvmrc` 与 `package.json`，依赖固定在 `package-lock.json`。Angular 的运行环境要求见[官方版本说明](https://angular.dev/reference/versions)。

```powershell
nvm use 22.22.3
npm ci
npm run dev
```

开发前端监听 `0.0.0.0:4200`，本机页面为 `http://127.0.0.1:4200`，局域网使用 `http://<本机局域网IP>:4200`；后端为 `http://127.0.0.1:3000`，前端通过同源 `/api` 代理访问后端。`npm run dev` 同时启动两者；也可分别执行 `npm run dev:api` 和 `npm run dev:web`。后台有截图任务时可单独使用 `node node_modules/@angular/cli/bin/ng.js serve --host <本机局域网IP> --port 4200` 开启局域网前端，保持后端运行。

若尚无 `.env`，将 `.env.example` 复制为 `.env` 并填写 `LIVEGBS_URL`、`LIVEGBS_USERNAME`、`LIVEGBS_PASSWORD`。密码填写登录接口要求的参数值，后端原样传递；认证信息保留在本地 `.env` 中，文件已忽略提交。

| 配置 | 默认值或用途 |
| --- | --- |
| `HOST`、`PORT` | 后端监听地址与端口，默认 `127.0.0.1:3000`；修改开发端口时同步 `proxy.conf.json` |
| `LIVEGBS_TIMEOUT_MS` | 每次上游请求超时，默认 15000 毫秒 |
| `LIVEGBS_SMS_ID` | 视频流媒体节点编号，默认 `34020000002020000001`；CMS 主机与端口取 `LIVEGBS_URL` |
| `DATA_DIR` | 数据目录，默认项目下 `data/`，相对路径以项目根目录解析 |
| `ESSLD_PYTHON`、`ESSLD_UPSTREAM` | 本地识别使用的 Python 和 ESSLD 源码目录，默认 `data/essld/.venv/Scripts/python.exe` 与 `data/essld/upstream`，相对路径以项目根目录解析 |
| `MCP_HOST`、`MCP_PORT` | 独立 MCP HTTP 服务，默认监听 `0.0.0.0:3001` |
| `MCP_API_KEY` | 必填的 MCP 访问密钥，客户端通过 `Authorization: Bearer` 传入 |
| `MCP_ALLOWED_HOSTS`、`MCP_ALLOWED_ORIGINS` | 可选的额外服务主机名及浏览器来源，配置见 [MCP 使用说明](docs/MCP使用说明.md) |

生产运行及检查：

```powershell
npm run build
npm start
npm test
```

生产入口为 `http://127.0.0.1:3000`，Fastify 同时提供页面、Cesium 静态资源、业务接口与截图文件。数据库位于 `data/cctv.sqlite`，图片位于 `data/snapshots/`；备份时保留完整数据目录。

### 数据库初始化

新部署可在启动服务前执行：

```powershell
npm run db:init
```

脚本读取 `.env` 中的 `DATA_DIR`，默认使用项目下的 `data/`，通过现有存储模块创建完整表结构，再导入 [摄像头初始数据](scripts/initial-cameras.json)。初始数据来自当前已保存的 7 台摄像头：隘洲岛2、隘洲岛1、小蜘洲岛2、小蜘洲岛1、竹洲岛2、竹洲岛1、天津船闸，包含原始 ID、设备与通道编号、名称、最大倍率、经纬度、高度、P 轴前后倾和左右倾、默认朝向、T 偏移、画面 Roll 修正及原始创建和更新时间，数值保留数据库精度。

导入在同一事务中完成，已有相同 `serial + code` 的通道直接跳过，保留其现有配置，可重复执行；其他导入错误会回滚本次摄像头写入并以失败状态退出。初始化数据仅包含摄像头及其安装配置，截图、截图任务、识别记录、标绘和登录凭据需按各自部署或备份流程准备。后续要更新新部署采用的设备参数时，维护 `scripts/initial-cameras.json`；已部署数据库仍通过页面保存配置。

## 首版范围

1. 注册、编辑和选择摄像头，将设备标识、最大倍率 Z、安装位置、P 轴姿态、P/T 偏移和画面 Roll 修正保存到 SQLite。
2. 控制当前摄像头上、下、左、右及变倍，并定时回读真实 PTZ。
3. 根据安装位置、P 轴姿态、P/T 偏移、画面 Roll 修正、真实 PTZ 和接口视场角，在 Cesium 显示摄像头位置、朝向、视锥及可计算的地表覆盖范围。
4. 提供最佳观察、跟随摄像头和固定观察，支持修改安装标定参数后即时对照。
5. 获取快照，将图片、姿态和采样时使用的标定参数一起保存；支持多个 PTZ 控制点之间的线性插值，沿 P 递增逐点停稳采样；提供任务分组、进度、暂停／继续、历史回看、单图删除及任务全景拼接。
6. 直接解析拼接的 WS-FLV 直播，在 Cesium 视锥内显示随真实 PTZ 与安装参数变化的视频截面。
7. 通过 MCP 按摄像头和时间段读取截图，由连接端 AI 标注海天线，生成可复核的 P 轴倾斜数据。
8. 从截图任务创建本地 ESSLD 识别任务，在页面逐图或通过全景图编辑海天线、复核连贯性、忽略异常图片，联合生成 P 轴前后倾、左右倾、T 偏移和画面 Roll 修正，并手动应用最终结果到该摄像头配置。
9. 导入 GeoJSON 标绘图层，独立管理名称及零个或多个摄像头关联，按摄像头保存显隐，在地图中显示和定位。
10. 后端接收固定项目 AIS 来源并适配为精简船舶数据；监控页面单选来源并在浏览器记忆，按摄像头 FOV 显示点，为当前追踪船建立估算长方体；开启追踪后按位置或船艏变化定时重新定位。

参考项目中的保护区、鱼圈和识别框属于原业务，不纳入本工具首版。AIS 采用下述独立数据源入口。海天线可由网页调用本地 ESSLD 后人工复核，也可由连接 MCP 的视觉 AI 标注；数值拟合由本工具完成。

- 左侧菜单：固定 56 像素宽的图标栏，提供三维视场、设备、截图记录、截图任务、识别任务和标绘管理图标；设备和截图图标展开对应侧栏，任务图标进入对应页面。识别页和标绘管理页使用完整工作区，隐藏实时云台表单；识别页宽屏分为左侧任务列表、中间截图复核与横向缩略图、右侧安装参数，三部分分别滚动。窄屏将安装参数排在复核区下方，小屏将任务列表改为顶部横向排列。
- 中间 Cesium：高德卫星底图上展示摄像头、视场、直播视频截面和当前摄像头关联的标绘，提供最佳观察、跟随／固定观察；历史快照在原直播截面的位置显示截图。下方保留直播状态、重连、不透明度控制；实时模式提供最新截图预览，历史模式显示采样时间、尺寸、PTZ、原图入口及截图不透明度。工具栏“直播融合”按钮开启／关闭视频纹理及媒体连接；“图层”面板提供持久显隐、定位、刷新／重试及标绘管理入口；“临时点”工具提供点位及船体尺寸的添加、编辑、定位、云台手动追踪、单点删除与清空，展示船体海面轮廓、目标 P/T/Z 及预计占比。
- 最右侧容器：顶部固定云台控制区，方向键按上／下／左／右排列，中间留空，加减键位于下方，截图按钮位于方向控件旁边。方向和变倍按钮按住控制、松手停止，下方提供速度、PTZ 回读间隔及独立“停止”按钮；“精确 PTZ（高级）”默认折叠，展开后手动输入 P/T/Z 并提交。控件下方显示只读的 PTZ、视场角及回读时间。
- 安装表单顺着控制区向下排列，可滚动编辑 P 轴前后倾、左右倾、默认朝向（P 偏移）、经度、纬度、高度和设备标识；“高级标定”中编辑 T 偏移与画面 Roll 修正，默认均为 0。底部提供保存按钮，错误及保存状态在对应操作附近显示。
- 实时画面右侧“自动截图”用紧凑卡片设置至少两个有序 PTZ 控制点，支持手填、读取当前 PTZ、增删和排序；最大 P 间隔与预计张数并排显示，下方提供开始截图和查看任务按钮。逐段递增并支持跨 0°，T/Z 同步插值；任务页以对齐表格展示控制点，并显示间隔、状态及图片，提供暂停、继续、取消和手动创建识别入口。
- 截图记录按一次接口调用分组；自动扫描每组包含多张，手动截图与旧记录各自作为单张组。分组和组内图片均分页加载，默认折叠。截图记录及任务详情中的图片支持右键“删除截图”，删除当前历史图后退出该图预览；正在扫描的设备需先暂停或停止再删除。

“云台 P 轴姿态”、T 偏移、画面 Roll 修正及 AIS 面板“船体尺寸”旁提供圆形问号。鼠标悬浮、键盘聚焦或点击问号可查看对应手绘说明图，移动到图上可继续阅读；移开并离开焦点、按 Escape 或点击外部可关闭。浮层位于浏览器顶层，避免被表单滚动区域裁切。

相机参数插图以现场的白色鹅颈支架、灰色上壳和黑色悬挂式云台为外形参考，分别说明整根 P 轴的安装倾斜、T 读数与实际俯仰的固定偏差，以及绕最终光轴的画面 Roll。AIS 尺寸图以船舶俯视图标明 AIS 天线至船艏／船艉的 A/B、至左舷／右舷的 C/D，并以侧视图说明海面以上的船高。四张 PNG 随应用部署，使用内置 image_gen 生成，维护提示词见[生成提示词](docs/calibration-help-prompts.json)。

## 底图与坐标

底图使用高德卫星影像 `https://webst0{s}.is.autonavi.com/appmaptile?style=6&x={x}&y={y}&z={z}`，子域名为 1～4，最高瓦片级别为 18。

高德使用 [GCJ-02 坐标系](https://lbs.amap.com/faq/advisory/others/39838)。本项目沿用参考场景的本地近似转换，仅在影像层进行底图偏移：选取瓦片时将 WGS84 转为 GCJ-02，计算瓦片地理边界时将 GCJ-02 逆算回 WGS84，瓦片原生 WebMercator 网格保持原样。适配通过独立的 `AmapTilingScheme` 和 `AmapProjection` 实现。

摄像头位置、视锥、海面交点、标绘及数据库中的安装参数统一保持 WGS84。转换适用范围外保持原坐标；实际地物对齐和现场精度仍需验收。

## GeoJSON 标绘

在“标绘管理”选择单个 UTF-8 `.geojson` 或 `.json` 文件，填写管理名称并勾选摄像头后导入；默认勾选当前摄像头，也可全部取消。一个文件生成一个独立图层，重复导入生成新图层。原文最大 10 MiB，允许 UTF-8 BOM，原文及文件中的 properties、样式和高程写入 SQLite 保留；管理名称与原文分开保存。非法 UTF-8、JSON、几何、坐标或关联会明确报错，失败时保留表单。

管理页列出全部图层及来源文件、要素数和关联摄像头。改名与编辑关联使用独立草稿，保存后生效；解除关联只影响该摄像头，保留未关联图层。名称由全部关联摄像头共用。“删除图层”确认名称及受影响摄像头后，删除原文和全部关联。

管理页的摄像头选择只作为显隐与定位上下文，默认跟随当前摄像头；未关联该上下文的图层需先编辑关联。新关联默认显示，各摄像头分别保存显隐，写入成功后更新地图；失败保留已保存状态。地图仅加载当前摄像头关联的图层，切页、刷新或服务重启后从已保存记录恢复。

定位隐藏图层时先保存为显示，再通过设备切换及离页保护进入地图，成功后关闭跟随观察。定位只移动地图观察相机，不下发 PTZ；没有有效几何时明确提示。支持 Feature、FeatureCollection 与标准点、线、面、GeometryCollection；无高程的点和面贴地，已有高程按米制 WGS84 椭球高度显示，样式按下述场景规则使用。仅接受 WGS84／CRS84，不进行坐标系转换、手绘、要素编辑、样式编辑或导出。

标绘区域（Polygon、MultiPolygon）统一使用黄色（`#ffff00`）填充，关闭外轮廓和内环轮廓线，保留原有内孔。`fill-opacity` 缺省或为 0 时使用 25% 不透明度，其余沿用文件值。二维区域保持 WGS84 零高程，三维区域保留已有高度，原始 GeoJSON 不变。

独立标绘线使用朝向地图观察相机的标准屏幕宽度折线，显示线宽至少为 4 像素，保留更粗的文件线宽、颜色和透明度。二维线保持 WGS84 零高程，深度重合或被海面遮住的部分采用同色、同虚线样式的深度失败材质继续绘制；三维线保留已有高度与深度遮挡规则。线支持双值 `stroke-dasharray`，例如 `"8 6"` 或 `[8, 6]`。

列表与原文缓存在 Viewer 外，单个图层加载失败不影响其他图层，可在图层面板刷新／重试。导入校验与接口限制见[接口文档](docs/API.md)。浏览器布局、真实 WebGL、复杂文件性能和现场地物对齐仍需验收。

## AIS 数据源与追踪船体

三维视场工具栏的“AIS”打开来源选择与船舶详情。整个监控页面一次选择一路来源，当前可选“天津船闸 AIS”和“大沽 AIS”；首次选择第一路“天津船闸 AIS”，也可选择“不显示 AIS”。浏览器按项目记住选择，刷新恢复；已移除的旧来源恢复为关闭。切换摄像头保留来源，清除上一摄像头的追踪标记；离页或进入历史截图时关闭页面订阅并隐藏实时目标，返回实时重新取得完整快照。

后端 [project.mjs](server/project.mjs) 固定项目身份、WS 地址、适配器、UTC+08:00 时间解释、10 分钟目标有效期、2 公里显示范围和船体估算参数。不同部署在后端更换配置及适配实现，前端消费同一来源目录和船舶模型；来源地址不下发前端，不提供来源编辑界面。目标只缓存在内存，不入库或保存 AIS 历史。页面订阅初始化失败时显示具体原因和“重新连接”按钮，不保留“正在连接”的状态。

两路来源均只消费 `api=1` 的 AIS／融合批次，分别按 MMSI 合并，较旧记录不覆盖新位置，不合并不同来源的同 MMSI 船舶；其他消息类型、空批及某船暂未出现在一批中不代表删除。适配器将误报为 0 的船艏替换为同船当前缓存中的旧船艏，没有旧值时为缺失；经纬度、时间及速度仍照常更新。其他无效方向、尺寸或速度保留为缺失值，0 节速度仍有效；时间使用明确偏移解析，过期初始记录不会因重新接收变成实时目标，旧船艏随目标过期一并清除。来源断开后清空该来源目标及旧船艏并公开状态，自动重连；多个页面共享后端同一来源连接。下游使用同源 SSE，携带统一完整快照，支持重连恢复，服务关闭释放订阅和连接。接口见 [API](docs/API.md#ais-数据源接口)。

普通船舶仅使用点；只有当前追踪船在估算或手动尺寸、船艏有效时建立长方体。追踪盒和轮廓在视频合成后绘制，兼容未启用顺序无关透明的正常回退路径；仍使用实际地理尺寸、观察投影和独立点选通道。最佳观察、跟随和固定观察均按当前摄像头真实 PTZ/HFOV/VFOV 及 2 公里范围筛选，近处普通点保留，兼顾船体边界，不按 Cesium 自由观察相机扩大发送范围。缺少有效 PTZ/FOV 或目标被椭球遮挡时不绘制。

ABCD 默认按来源参数估算，假定天线位于中心线、距船尾为船长 10%，即 `A=0.9L`、`B=0.1L`、`C=D=0.5W`；默认模拟高 10 米，可在后端按来源覆盖比例和高度。AIS 面板“船体尺寸”可手动填写 A/B/C/D 及船高，点击“应用尺寸”后用于船体显示和追踪取景，“恢复估算”重新使用最新来源长宽及默认参数。A/B 是 AIS 报告位置至船艏／船艉的距离，C/D 是至左舷／右舷的距离，单位米；每项允许为 0，但 `A+B`、`C+D` 和船高必须大于 0。手动尺寸按数据源与 MMSI 保留在当前网页内存，AIS 更新、切源或切换摄像头不会覆盖，刷新或关闭网页后清除，不写数据库或浏览器存储。

船体长宽分别为 `A+B`、`C+D`，中心相对 AIS 位置沿船艏移动 `(A-B)/2`、向右舷移动 `(D-C)/2`，底面在零高程，中心高度为船高的一半。默认估算向船艏前移 `0.4L`；手动尺寸可补足来源缺失的长宽。原始 AIS 经纬度、长宽等字段不改写；缺少有效船艏或可用尺寸时降级为报告点，不以 COG 冒充船艏。手动填写也不代表船体、天线位置及现场精度已核验。

点击点或按 MMSI 查找后，点击“开始追踪”立即定位一次，此后每次调用结束等待 1 秒检查最新目标。仅经纬度或船艏变化时重新下发 P/T/Z；仅来源时间、航速或长宽更新不触发定位，本源被过滤的 0 船艏也不单独触发。当前正在追踪时，应用手动尺寸或恢复估算会按新参数重新定位一次，并使旧参数下尚未下发的请求失效。每次先回读 PTZ，完成后再取来源快照；有完整几何时瞄准船体中心，按当前采用的长宽高估算横纵占比均不超过 50% 的 Z，并受摄像头保存的最大 Z 限制，否则定位报告点并保留倍率。定位调用串行执行，期间多次变化只处理最新状态，不积压中间位置。

“停止追踪”在等待回读时也可使用，取消后续定位和追踪标记。停止按钮、手动方向／变倍／精确定位、保存配置、启动截图扫描、切源、切换摄像头、改选目标、历史、离页或隐藏网页会结束追踪，使尚未下发的旧请求失效；停止后重新选择同船也不恢复旧请求。目标过期、来源断开或定位失败时结束追踪，重新开始须显式点击按钮；已经下发的指令仍以实际回读和现场为准。

时间偏移、有效期、模拟高度和天线比例是当前部署默认值，不代表已验证线上服务版本、船端观测时刻、实际天线位置或现场精度。已完成 HTTP／几何回归、类型及构建检查，以及真实来源的有限只读适配验证。源证据与局限见[协议研究](.scratch/ais-data-source/research/upstream-contract.md)；浏览器交互、真实 WebGL、云台动作及取景精度仍需现场验收。

## 实时视频

采用参考 Cesium 场景 `core/player.ts` 的媒体链路，使用固定版本 `flv.js 1.6.2` 直接[解析 FLV over WebSocket](https://github.com/bilibili/flv.js/blob/master/docs/livestream.md)。FLV 解复用并转封装为 MediaSource 数据后，由浏览器将 H.264 视频解码到原生 `HTMLVideoElement`，Cesium 直接使用该元素作为视频纹理，整个过程只建立一条媒体连接。

```text
WS-FLV → flv.js → MediaSource / video → Cesium 视频纹理截面
```

视频截面位于摄像头前方 500 米，四角按同一安装姿态、P/T 和接口 HFOV/VFOV 计算，与视锥端面一致；旋转 P、T 或编辑安装参数时同步更新，不跟随地图观察相机转动。完整画面的横纵坐标分别映射接口 HFOV/VFOV，与地图空间点采用相同的透视关系。状态栏可调视频不透明度，方便与底图对照；最佳观察沿用约 65% 的视口占比。

对照视频中的标绘位置时，使用“最佳观察”或跟随观察，将地图视点置于摄像头安装位置，并统一两边的标绘坐标、安装参数、PTZ 和 HFOV/VFOV。移动地图视点后，固定的视频截面与实际海面处于不同距离，会产生视差。

截面显示关闭深度测试，避免低位摄像头的视频画面穿入近似海面后被裁掉；是否位于地球背面按摄像头位置判断。该截面用于视角对照，不表示视频已经贴合地形或通过了地物标定。

后端 `GET /api/playback?cameraId=<本地摄像头ID>` 根据 CMS 配置和该设备保存的 `serial/code` 拼接地址。未传 `cameraId` 时使用默认设备：

- `serial = 34020000001320000088`
- `code = 34020000001320000001`
- `sms_id` 默认 `34020000002020000001`，可通过 `LIVEGBS_SMS_ID` 修改。

```text
ws[s]://{cms_ip}:{cms_http[s]_port}/sms/{sms_id}/ws-flv/hls/{serial}_{code}.flv
```

CMS 主机、端口与 HTTP／HTTPS 协议取 `LIVEGBS_URL`，分别映射为 `ws`／`wss`。默认设备的地址示例为：

```text
ws://192.168.1.15:10000/sms/34020000002020000001/ws-flv/hls/34020000001320000088_34020000001320000001.flv
```

直播采用当前摄像头已保存的 serial/code；只有表单中的通道标识也与直播源一致，且存在有效位置、姿态和接口视场角时，才显示视频截面。切换摄像头时取消旧地址请求，清空媒体源及纹理引用，由媒体组件销毁旧 MediaSource 与 WebSocket，再取得新设备地址并连接；旧 HTTP 响应不能覆盖新设备。注册新设备时停止当前直播；保存设备或通道编号后重新取流，只修改安装参数时保持现有媒体连接。

进入历史记录时将直播替换为该条记录的截图，使用采样时的安装参数、PTZ 和视场角放置在同一截面，完整原图按两个独立 FOV 映射。历史图片来自对应记录的原图地址。

浏览器直接建立媒体 WebSocket，不请求取流地址接口，也不拼接登录 token；PTZ、控制和截图 API 的认证仍由后端处理。HTTPS 页面需将 CMS 配置为其可用的 HTTPS 地址及端口，以生成 WSS 地址。

媒体默认静音自动播放，新解码帧触发 Cesium 显式绘制，不重复拉流。关闭融合、进入历史快照或组件销毁时，撤掉视频纹理、帧回调、MediaSource 及 WebSocket；重连先释放旧连接，再建立新连接。分辨率变化时重新创建纹理，避免沿用旧尺寸。播放或纹理上传失败时明确显示错误，可重新连接；纹理失败不停止底图与云台界面。截图继续使用右侧截图按钮，经后端保存图片地址、PTZ 及安装参数。

播放依赖浏览器 MediaSource 和当前 H.264 编码支持；其他视频编码不作兼容承诺。浏览器实际解码、WebGL 纹理上传与地物对齐仍需现场验收。

| --- | --- | --- |
| 设备标识 | 本地 ID、名称、LiveGBS `serial`、通道编号 `code` | `serial`、`code` 均按字符串保存；本地 ID 不绑定第三方编号 |
| 安装位置 | 经度、纬度、高度 | 经纬度统一为 WGS84，高度单位米，采用 WGS84 椭球高程；海域以零高程近似海面，其他高程基准须在填写前换算。位置可留空完成注册，填写完整后才生成投影 |
| P 轴姿态 | 前后倾、左右倾 | 描述 P 轴的安装倾斜，角度以度保存到数据库，运行时生成旋转矩阵 |
| 默认朝向 | 安装坐标系的基准方位（P 偏移） | 角度以度保存到数据库，先旋转整个底座的安装朝向，再应用该安装坐标系中的前后倾、左右倾 |
| T 偏移 | 局部 T 零位修正 | `tiltOffset`，单位度，正值上抬；局部俯仰旋转为 `Rx(tiltOffset - Tilt)` |
| 画面 Roll 修正 | 绕最终光轴的固定旋转 | `imageRoll`，单位度，在局部 P/T 之后应用 `Ry(imageRoll)`；单通道不区分主副镜头 |
| 实时视场角 | HFOV = `HorizontalFieldAngle`，VFOV = `VerticalFieldAngle` | 直接使用 LiveGBS PTZ 接口返回值，作为三维投影的唯一视场角来源，与同次回读的 P／T／Z 一起更新 |
| 实时状态 | 原始 PTZ 响应、归一后的 P／T／Z、采样时间、请求状态 | 与数据库中的安装参数、控制目标及页面格式分开保存 |

通道配置以 `code` 为主；快照接口也支持通道序号 `channel`，它与 `code` 是两种标识，不能相互当作编号使用。若采用 `channel`，需明确其与当前设备通道的对应关系。

朝向采用真北 0°、向东 90°约定。当前适配按 P／T／视场角为度、P 顺时针处理；设备原始 T 为 -90°～90°，负值上抬、正值下俯，按有符号数直接比较和下发，不按环形角度处理。P 的真实方向与安装零位仍需现场复核。默认朝向作为安装方位旋转整个底座，前后倾和左右倾在该安装坐标系下定义，再绕此固定 P 轴应用设备回读 P。视锥及其他投影使用同一结果，原始 PTZ 和真实控制目标保持设备读数语义。

共用旋转链为 `Rz(-panOffset) × Rx(pAxisPitch) × Ry(pAxisRoll) × Rz(-Pan) × Rx(tiltOffset - Tilt) × Ry(imageRoll)`，再由当地 ENU 转到世界坐标。前三项生成固定安装矩阵，与参考场景 `createInstallationRotation()` 的 Z-X-Y 约定一致；默认朝向只在安装矩阵中应用一次。P 轴安装、T 零位及画面 Roll 的旋转次序固定。已有数据库启动时补齐 `tiltOffset/imageRoll` 两列并初始化为 0；历史截图缺少两项时按当时的零修正读取，不改写原始截图元数据。

与参考算法对照时，使用相同的安装位置、姿态、PTZ 和 HFOV/VFOV；本工具采用图像中心主点、零额外镜头 P/T 修正及零光心位移。参考项目的倍率表、主点偏移和镜头位移属于独立光学输入，对照时须统一这些输入。参考数值回归由参考原函数生成夹具，运行测试不依赖本机外部参考目录。

“设备信息 → 最大倍率 Z”配置当前摄像头的倍率上限，最小为 1，点击“保存配置”后生效并持久保存。旧库启动时补齐 `maxZoom`，名称为“天津船闸”的设备初始化为 32，其他设备为 73；已有自定义值不随改名或重启重置。新注册表单默认 73，可按设备能力修改。自动倍率使用已保存的上限，精确定位及扫描下发拒绝超限 Z；连续变倍按钮仍发送按住／停止指令，机械终点由设备处理。图像尺寸取实际快照。缺少有效位置、姿态或接口视场角时，明确显示缺项，当前实时投影不可用。

## 表单保存

1. 进入调试页或切换设备时，从后端加载该通道在 SQLite 中保存的设备信息、最大倍率 Z 和安装参数。
2. 修改 P 轴前后倾、左右倾、P/T 偏移、画面 Roll 修正、经纬度或高度时，使用表单草稿即时预览；修改这些参数不下发云台指令。
3. 点击“保存”后，由后端校验并将当前通道的这些字段作为一次完整更新写入数据库，成功后以返回的数据库记录更新已保存状态。保存失败时保留草稿并显示错误，不提示保存成功。
4. SQLite 中的记录是已保存配置的唯一来源；刷新页面、切换设备后重新进入或重启服务时均可恢复。数据库保存角度及位置原值，旋转矩阵在运行时派生。

## 调试流程

### 姿态回读与控制

1. 选择摄像头后立即读取一次真实 PTZ，随后按右侧“PTZ 回读间隔”轮询，默认 10 秒，可填写 1～3600 的整数秒，编辑完成后生效；设置在当前页面会话内有效，刷新后恢复默认值。显示最新读数、回读时间与本次请求耗时。
2. 同一设备的回读请求不重叠，前一请求未完成时跳过本轮；修改间隔只重建定时器，保留正在执行的回读。切换设备或离开调试页时停止旧轮询，旧响应不能覆盖新设备状态。
3. 方向和变倍按钮按下时调用 `/api/v1/control/ptz`，分别发送 `up/down/left/right/zoomin/zoomout`；松手发送 `stop`。控制速度为 0～255 整数，默认 129，不需要先回读或计算相对角度。鼠标移出、触摸移出或取消、键盘松开、窗口失焦和页面隐藏也结束当前按住；键盘 Space／Enter 按住可控制，重复按键不重复发送启动。离开页面时使用 keepalive 请求发送停止。
4. 每次按住绑定启动时的设备。松手立即请求停止；启动请求仍在途时，后端将停止排在该请求之后，前端在启动结束后补发一次停止，处理快速点击和回包迟到。启动失败也尝试停止；停止失败显示错误并保留控制锁，可点击“停止”重试。服务正常关闭时会尝试停止尚未结束的连续控制。
5. “精确 PTZ（高级）”点击展开后提供独立 P/T/Z 表单，填写数值或主动点击“填入当前读数”，点击“发送精确定位”才调用 `ptzprecise`。表单按设备原始参数直接提交，不自动叠加安装修正。临时点“追踪”先通过安装模型反算原始 P/T，再复用同一精确定位接口。P 范围为 0～360°，T 为 -90～90°、负值上抬，Z 为 1 至该摄像头已保存的最大倍率；设备的进一步机械限制以现场为准。
6. 控制请求目标和设备回读分开显示；请求接受不代表设备已到位或已停稳。连续控制、精确定位及停止期间保持 PTZ 回读，截图期间暂停轮询。回读失败时保留最近读数并标记过期；连续方向控制及停止不依赖旧 PTZ 值。
7. 同一通道的连续控制、精确定位、截图和配置保存互斥；连续控制的锁保持到 stop 成功。停止请求可在启动请求仍在途时接收，不因控制锁返回 409。停止失败时仍可重试停止。

### Cesium 视场与最佳观察

“临时点”按输入的 WGS84 经度、纬度在椭球零高程显示黄色点和编号标签。经度范围为 -180°～180°，纬度为 -90°～90°，允许同时添加多个点，也可编辑已有点。定位临时点时切换为固定观察，只移动地图观察相机。点位及船体尺寸仅存在当前网页内存中，切换摄像头或菜单后保留，删除、清空、刷新或关闭网页后移除，不写数据库或浏览器存储。

每个临时点的目标 P/T 随当前摄像头位置、高度、安装参数及真实 PTZ 更新。点击“追踪”时重新回读 PTZ，按 WGS84 光心到零高程目标的方向逆解固定 P 轴姿态及 P/T 偏移，只在 T -90～90° 内选择更接近当前 P/T 的合法解，随后发送一次原始 P/T/Z 精确定位。普通点保留该次真实倍率；填写船体尺寸的点采用下述自动倍率。上抬负 T 原样保留，无合法解时明确报错，不将越界值截到边界。画面 Roll 不改变中心指向，P/T 反算不依赖 FOV。缺少有效参数、点位与光心重合或目标被椭球遮挡时明确报错；设备通道草稿与已保存配置不一致、历史模式、过期回读、截图扫描或其他控制期间不可追踪。参数变化只更新预览，设备动作由用户每次点击触发；发送成功不表示已到位，仍以实际回读和现场为准。

在“船体尺寸 / 自动倍率”填写船长、船宽和船艏朝向；长度单位为米，朝向采用真北 0°、顺时针增加。船高可选，未填写时保留缺失状态，并按海面矩形估算，不包含船体上部。经纬度作为船体海面中心，在当地 ENU 建立矩形或含船高的包围盒，以追踪后的姿态投影全部角点，综合斜距、朝向、安装倾斜、画面 Roll 及实际 HFOV/VFOV 估算尺寸占比；在当前摄像头已保存的最大 Z 内，选择横向、纵向均不超过画面 50% 的倍率，向下取 0.1 倍档。若 1 倍仍超过占比限制，或船体范围穿到镜头后方，则明确失败，不生成假定可用的倍率。

倍率推算使用同次回读的 Z/HFOV/VFOV，按焦距与 Z 成比例近似。页面显示斜距、目标倍率及预计宽高占比；这些值约束的是输入尺寸与该光学近似下的投影，设备真实 Z/FOV 曲线、实际船体形状和船高仍需现场验证。原图、原始 PTZ 和接口 FOV 保持原值，尺寸不上传后端；保存目标点修改或删除目标时，回读后尚未下发的旧追踪失效。

- 使用安装位置、P 轴姿态、P/T 偏移和画面 Roll 修正生成位置、方向及上向量，结合接口视场角生成视场；修改安装参数只重算模型，不改写设备 PTZ。
- 最佳观察参考 `focusVideo()`：主相机置于配置的安装位置并沿当前成像方向观察，结合容器宽高比扩大观察视场，参考占比约为视口的 65%。观察视场的调整不能反写接口回读的 HFOV／VFOV。
- 跟随观察在当前设备有效姿态或视场角变化时更新主视点；固定观察保留主视点，继续更新视锥。切回跟随或点击最佳观察时重新对准。
- PTZ 及视场角相同时不重复创建视锥、实体或 Viewer；窗口尺寸变化时同步视口与观察参数，退出页面释放自身资源。
- 地面覆盖线采用 WGS84 椭球零高程近似海面，只显示前向 10 公里以内的有效交点。当前未接入地形高程，不能据此认定陆地遮挡与覆盖范围准确。

### 截图与样本保存

截图流程为“设备停稳 → 回读 PTZ → 请求实时快照 → 再次回读 PTZ → 保存图片及样本”。截图期间避免继续发送本工具的控制指令；前后回读用于发现姿态变化，不能证明图片与 PTZ 严格同步。

每条样本至少保存：

- 设备本地 ID、当时的名称及 `serial`／通道标识。
- 原始图片文件、实际宽高、格式及后端生成的访问地址。
- 快照请求开始／结束时间、前后 PTZ 原始值与回读时间；响应提供 `Channel-Snap-Time` 时保留原值。
- 采样时接口回读的 HFOV／VFOV，以及实际用于该样本的经纬度、高度、P 轴前后倾、左右倾、P/T 偏移和画面 Roll 修正副本，避免后续改配置后无法还原样本；表单尚未保存时标明样本使用草稿参数。
- 姿态是否变化、是否采用表单草稿和时间对应尚未验证的状态。

`channelsnap` 已实测返回图片二进制，由后端保存后生成本工具的访问地址。图片保存与元数据写入都成功才返回成功；失败时清理本次产生的文件或记录，避免留下不可访问的样本。

历史回看采用采样时的参数与姿态，截图显示在中间 Cesium 原 CCTV 直播截面的位置，可调截图不透明度并打开原图。历史数据明确标记，安装表单及云台控制只读；切换记录时清除上一张画面，图片加载失败显示错误；点击“返回实时”清除历史纹理，恢复当前草稿、最新回读及直播开关状态。设备配置变更不修改已保存样本。

### 自动截图与任务

在实时右侧“自动截图”表单按顺序设置至少两个 PTZ 控制点。默认显示两个待设置点，可增加、删除和上下排序；每点可手填设备原始 P/T/Z，或点击“读取当前 PTZ”。切换摄像头后点位和间隔恢复初始状态，路径不作为预设保存。

最大 P 间隔默认 5°。每段沿 P 递增方向均匀采样，结束 P 小于起始 P 时跨 0°；T/Z 按同一进度线性变化。例如 (P=10°,T=0°,Z=2) 到 (20°,4°,6)，最大间隔 3°时，实际 P 间隔 2.5°，依次采样 (10°,0°,2)、(12.5°,1°,3)、(15°,2°,4)、(17.5°,3°,5)、(20°,4°,6)。

每个控制点均截图，相邻两段共用点只拍一次。350°→10°跨度为 20°，10°→350°跨度为 340°；相同 P 及 360°→0°是无效零跨度，不支持仅改变 T/Z 的段。0°→360°表示完整一圈，首尾各拍一次。两点填写相同 T/Z 可定义固定 T/Z 扫描。页面开始前显示预计总张数，单次最多 10000 张；最大 P 间隔只规定目标密度，不保证不同倍率下画面连续覆盖。

开始后后端冻结控制点、最大间隔、全部逐点目标和采样标定副本。每点通过精确 PTZ 定位，至少连续两次回读到位，并满足默认 1000 毫秒的稳定窗口后抓图；再次回读确认未变化才保存。定位默认等待 30000 毫秒，失败保留已保存图片。各采样目标线性变化不代表设备在精确定位之间按同步线性轨迹运动，图片与 PTZ 的严格同步仍为 `unverified`。

任务不依赖网页保持打开。暂停等待在途定位或抓图返回并确认 stop 成功后释放设备；继续从下一个未完成点执行，使用原冻结计划，表单修改不改变原任务。任务页显示进度、现存图片、控制点和最大间隔；删除截图只减少现存图片数，不会使继续任务重拍。完成后保持最后位置，不自动回起点。

结束、失败、取消及服务正常关闭均尝试停止云台；停止失败保留设备占用，可通过“停止”重试。正常关闭取消执行中的任务；异常重启标记为“已中断”，暂停状态保留，均不自动转动设备。暂停、失败及中断任务可手动继续；已经拍满时“确认停止并完成”仅重试停止和完成收尾，不重复定位或补拍。通道标识改变后拒绝继续旧任务。同一数据目录只运行一个业务后端，独立只读 MCP 可同时运行。接口见 [API](docs/API.md#自动截图与任务接口)。

新多点任务结束后，在任务页手动创建独立识别任务，复核标注并生成安装参数。已有普通及两阶段海天线任务仍保留原采样计划和恢复行为；历史海天线任务完成后的自动识别关联保留，历史预扫粗结果在页面仅供查看。

任务详情的“任务截图”旁提供“生成全景图”按钮。任务暂停或结束后，至少有两张图片即可生成；会自动翻页读取本任务全部现存截图，按采样顺序处理。使用每张截图保存的安装姿态、P/T、T 偏移、画面 Roll 及 HFOV/VFOV，沿用共享旋转模型将画面投影到同一水平圆柱面，重叠区域按边缘权重融合。安装经纬度和高度不参与这一远景旋转拼接。

生成过程显示进度并可取消，图片逐张解码和释放；结果支持横向滚动查看及下载 PNG。浏览器内计算，原图和数据库记录保持原样。画布最多 16384×4096，总像素不超过 1600 万，长任务按比例缩小；删除图片、继续采样、切换任务或离开任务页时清除旧预览及释放资源。截图读取失败或生成期间记录发生变化时明确报错，刷新后重试。已删除或未拍摄的中间视野保持透明，运动目标、近景视差、缺少重叠及标定误差仍可能产生接缝；画面包含竖直方向时不支持水平圆柱全景。

### 海天线与辅助标定

本工具提供只读 Streamable HTTP MCP，默认监听独立的 `0.0.0.0:3001`，供局域网内其他 MCP 客户端连接。MCP 读取已存在的 SQLite 数据库和截图文件，将原图以 MCP 图片内容返回，由连接端具备视觉能力的 AI 识别海天线，再调用数值工具生成 P 轴前后倾、左右倾。MCP 不调用外部模型，也不下发设备控制或改写摄像头配置。

配置 `.env` 的 `MCP_API_KEY` 后，在服务端运行 `npm run mcp`。当前局域网地址为 `http://10.10.101.132:3001/mcp`，客户端配置示例见 [mcp.config.example.json](mcp.config.example.json)：

```json
    "cctv-tilt-calibration": {
      "url": "http://10.10.101.132:3001/mcp",
      "headers": {
        "Authorization": "Bearer <MCP_API_KEY>"

    }
  }
}
```

MCP 与网页应用共用 `.env` 中 `DATA_DIR` 指向的数据目录，先通过网页注册设备并保存截图。HTTP 服务按请求创建只读 MCP 实例，无需会话 ID，支持多个客户端；认证、Host/Origin 校验及协议处理使用独立服务入口。当前本机的实际客户端连接配置保存在忽略提交的 `mcp.config.local.json` 中。完整启动、参数、直接 HTTP 调用和排错见 [MCP 使用说明](docs/MCP使用说明.md)。本机 stdio 入口仍可通过 `npm run --silent mcp:stdio` 使用。

| 工具 | 用途 |
| --- | --- |
| `list_cameras` | 列出摄像头、当前安装参数、截图数量和可用时间范围 |
| `query_snapshots` | 按 `cameraId/startTime/endTime` 查询截图，可用 `groupId` 限定一次任务，支持分页；开始包含、结束不包含 |
| `get_snapshot` | 返回原图图片内容与采样 PTZ、FOV、尺寸和时间，供 AI 看图 |
| `estimate_p_axis_tilt` | 接收截图 ID 和海天线归一化点，从数据库读取采样参数并拟合倾斜 |

操作流程：

1. 确定摄像头和时间段；起止时间须带时区，例如 `2026-11-09T11:00:00+08:00`。筛选依据为本工具的 `createdAt`，不使用无时区的快照响应头时间。
2. AI 读取原图，识别远处海天线，每张图至少标注两个点。`x = 像素横坐标 / 图片宽度`、`y = 像素纵坐标 / 图片高度`，左上角为原点，数值均为 0～1；点的横向跨度至少为图宽的 10%。看不清、遮挡或只有岸线时跳过，不能补造点位。
3. 选择停稳且海天线可确认的截图，工具排除 `poseChanged`、无效 PTZ/FOV 或设备通道不一致的样本。张数、不同 P 方向数和覆盖范围用于查看样本分布，拟合质量由实际收敛、可辨识性和残差决定；样本较少或方向集中时，对标注和固定参数误差更敏感。
4. MCP 拟合固定当前保存的经纬度、高度、P/T 偏移和画面 Roll 修正，使用采样时的真实 P/T 与接口 FOV，考虑 WGS84 椭球海平线的曲率影响。前端投影和拟合共用局部旋转模型。此 MCP 流程只估计 P 轴前后倾、左右倾，T 偏移与画面 Roll 需先复核保存。
5. 返回 `pAxisPitch`、`pAxisRoll`、总倾角、轴方向以及逐图残差。结果和标注仅通过 MCP 返回，不写回数据库或生成持久化报告文件；用户复核后在现有表单填写两个角度并保存。

只有 `status=estimated` 才返回安装角度；没有有效样本返回 `insufficient_data`，未收敛、不可辨识或均方根残差超过 5 像素返回 `unreliable`，后二者的 `installation` 为 `null`。即使通过拟合，结果也属于待复核估计，不能认定现场标定已经完成。

当前模型 `wgs84-horizon-p-axis-v3` 假定固定安装、P 轴朝上，前后倾和左右倾均在 -89°～89°内，并以默认朝向定义的安装坐标系为参考；T 偏移和画面 Roll 使用已保存值，主点位于图像中心，海面近似椭球零高程。T 偏移或画面 Roll 设置不准会影响 P 轴结果，本次不联合求解这两项。标定结果应与其输出的模型编号及安装旋转约定一起复核；更新拟合实现后，需重新连接 MCP 进程以载入当前模型。高度、绝对朝向、潮汐、折射、畸变和稳像裁剪未由海天线求解。详细参数及输出见[接口文档](docs/API.md#截图标定-mcp)。

## 本地模型识别与安装参数

该流程在网页完成，不需要 MCP。Python 环境与权重的安装步骤见 [ESSLD 环境说明](docs/MCP使用说明.md#essld-独立离线试跑)，Python 3.11 与依赖独立于 Node/npm。默认使用本机已经安装的 `data/essld/.venv/` 和 `data/essld/upstream/`；环境或源码移动后通过 `ESSLD_PYTHON`、`ESSLD_UPSTREAM` 指定。识别环境缺失或执行失败会明确显示错误。

1. 选择已暂停或已结束且有图片的截图任务，点击“创建识别任务”；已有的关联任务可直接打开。识别使用创建时的现存截图集合；后续采集新图需要创建新一轮识别。
2. 在“识别任务”查看进度。本地 CPU 模型任务依次执行，支持取消；手动创建的任务识别完成后复核并生成候选安装结果，不自动应用参数；历史海天线任务的自动关联仍按原规则处理。服务关闭或异常重启后保留已处理数据并标为中断，可从原截图任务创建新一轮识别。
3. 逐张复核原图上的线：橙色虚线为模型原始结果，红色实线为当前标注。拖动两端或输入 0～1 归一化坐标，横向跨度至少 10%；“重新画线”提供初始线，再根据原图调整。坐标和忽略状态可保存，切换任务、图片或菜单页面时先保存当前修改；保存失败则保留草稿并停止切换。
4. 可勾选“忽略此图”或恢复参与计算。模型未给出合法线、截图前后姿态变化时默认忽略；同一 T/Z/FOV 的附近最多 6 张图作为参照，至少 3 张参照时比较倾角及归一化高度的中位数与 MAD，门槛为 `max(3° 或图高 5%, 3 × 1.4826 × MAD)`，突变图默认忽略。多点采样可能逐点 T/Z 不同，该过滤不直接比较不同 T/Z/FOV 的图像行位置；这类路径仍需逐图复核。连续的岸线误识别仍需人工处理；自动忽略项可以人工重标并恢复。
5. 点击“生成安装参数”，使用全部未忽略、源记录仍存在的图片及实际 PTZ/FOV，联合求解 `pAxisPitch/pAxisRoll/tiltOffset/imageRoll`。固定 T/Z 的扫描可参与计算，张数、不同 P 方向数和覆盖范围用于查看样本分布。固定经纬度、高度和默认朝向，两个 P 轴倾角限制在 -89°～89°，T/Roll 在 -180°～180°。只有收敛、四参数可辨识且均方根残差不超过 5 像素时，页面展示可应用参数；样本较少或方向集中时，对标注和固定参数误差更敏感。
6. 截图任务的识别结果复核后点击“应用到摄像头”，仅保存四项安装修正，立即同步当前设备表单及三维投影；不发送 PTZ 控制、不修改原始读数或历史截图。历史预扫粗结果在页面仅供查看。标注变化会清除旧结果；配置变化、参与样本被删除、旧版本或重复应用均返回冲突，需按提示重新生成。

本地联合拟合模型为 `wgs84-horizon-installation-v1`；MCP 保持只估计两个 P 轴倾角的 `wgs84-horizon-p-axis-v3`。任务、模型原始标注、人工标注、忽略状态及计算结果均保存到 SQLite，重启后可继续复核。源截图被删除时识别任务保留标注记录，并在重新生成时排除该图。

识别结束后，复核区的“生成全景图”会先保存当前标注，再翻页读取该识别任务的全部截图与标注；至少两张原图仍存在时可生成，已忽略的图片仍参与背景拼接，已删除图片跳过。全景沿用截图任务的圆柱投影与画布限制，使用采样时保存的姿态和安装参数。各图当前海天线沿原图直线自动延长到左右边缘，再独立投影为红色线段，已忽略的标注显示灰色虚线；超出上下边界的部分裁切，不跨图补线或平滑。全景默认适应宽度，可放大后横向滚动、隐藏标注，点击线段或缩略图聚焦对应截图。

全景总览展示融合背景和各图海天线；聚焦编辑将当前截图按同一投影不透明置顶，显示蓝色轮廓和当前图的标注，周围保留全景背景，避免对着多图混合画面标线。左右各缩进图宽 3% 留缝，两个端点可上下拖动。“上一张／下一张”按现存截图的采样顺序切换，跨 0° 时也保持顺序，首尾不循环；切图前自动保存，保存失败时保留当前图和草稿，切换成功后保持缩放并将新图移到可见区域。

点击全景、线段或缩略图后可直接用键盘微调；左右方向键选择端点，上下方向键每次调整 1 个原图像素，Shift 调整 10 像素，Alt 调整 0.1 像素，Ctrl+S 保存。当前微调端点以实心圆点和“左端点／右端点”按钮状态标明，也可点击按钮切换。快捷键仅在全景聚焦编辑区域获得焦点时生效；隐藏标注、识别执行或请求处理中不允许调整。

端点位置通过同一圆柱投影反算为该原图的归一化坐标，与逐图编辑共用草稿、保存、撤销及切换前自动保存流程。自动延长和留缝属于展示转换，仅调整端点时更新人工标注，不改写模型原始结果。全景与原图标注实时同步，未保存状态显示在全景工具栏和单图编辑区；保存后需重新生成安装参数。

下方单图复核可显示采样顺序紧邻的上一张和下一张截图的只读端点、参考线；参照按各图保存的安装姿态和 PTZ/FOV 映射到当前原图，用不同颜色区分来源。端点在画面外时仍显示可见线段；图像已删除、没有有效标注或无可见重叠时省略该方向参照，忽略图保留其状态。参照可隐藏，只有当前图的正式端点可编辑，不自动连接或修改相邻图。

全景总览还可绘制一条直线或分段贝塞尔弧线，可以只覆盖全景的一段。初始弧线有两个端点和一个弯曲控制点；选中某段的点后点击“添加节点”，在该段中间拆分并保持原曲线形状，每段有独立的菱形控制点。内部圆形连接节点可移动，选中后点击“删除选中节点”合并相邻两段；首尾端点保留，最多支持 32 段。支持拖动、保存、撤销、隐藏、删除和重画；绘线与逐图编辑分开。全景参考线按真实投影映射到下方单图，保留各段实际曲线和可见片段，供人工对照，不自动变为单图正式标注或进入安装拟合。已保存的三点弧线可直接增加节点继续编辑。

参考线随识别任务独立保存，刷新、返回任务或重新生成全景后可继续调整，缩放和画布尺寸变化不会改变其对应方位。参考线使用独立版本，保存或删除不会清除安装结果；新一轮识别不继承旧任务的参考线。原图和正式标注的保存规则保持一致，错误会保留草稿供重试。

全景在浏览器内生成，可取消；生成期间暂时禁用标注编辑和安装参数操作。切换任务、刷新或离开识别页会释放预览及置顶图片资源；生成期间任务或标注版本变化、原图读取失败会显示错误，迟到的上一张图片不会覆盖当前图。全景仅辅助复核，不改变原始图片、采样姿态或安装拟合结果，也不代表标注连贯性与现场精度已通过验收。

通过数值检查不等于现场标定准确。山体、岸线、船体或近处海水上的错误线可能形成平稳序列；模型结果必须复核。高度、默认朝向、潮汐、折射、畸变、稳像裁剪以及截图/PTZ 严格同步均未由这四个参数解决。

## 前后端与存储职责

```text
Angular 页面 → Fastify → LiveGBS
                  ├─ SQLite：设备配置、标定参数、截图元数据、识别任务与标注、标绘原文及摄像头关联
                  ├─ 本地 Python / ESSLD：识别海天线候选
                  └─ 本地数据目录：原始截图文件
```

- 前端负责操作表单、交互状态、WS-FLV 解复用与浏览器解码、Cesium 视频纹理展示及展示边界的数据格式化。
- Fastify 负责 LiveGBS 认证、PTZ 回读与控制适配、快照转存和配置／样本持久化。LiveGBS 地址与凭据由后端配置，登录 token 由后端管理。
- token 缓存在后端内存中，并发请求共用登录；临近过期重新登录，上游返回 401 时重新登录并重试一次。网络故障和超时不自动重发控制指令。
- LiveGBS 原始响应与工具内部的业务数据分别处理，字段归一在接入边界完成；接口不返回表单专用的拼接文本。
- SQLite 按注册通道保存设备标识、经纬度、椭球高度、P 轴前后倾、左右倾、P/T 偏移和画面 Roll 修正，并保存截图元数据、标绘原文、管理名称、摄像头关联及各关联的显隐；截图文件存于后端数据目录，文件名由后端生成。两者共同组成持久化数据。
- 登录失败、回读失败、控制失败和保存失败分别暴露；不得用旧值伪装成功。

## 技术栈

- 前端：Angular 22.2.5 + Cesium 1.147.0。
- 后端：Fastify 5.12.8 + Node 内置 `node:sqlite`。

Node 22 中 `node:sqlite` 会输出实验性功能提示，数据库读写及重启恢复由接口回归验证。参考项目旧 Angular 11 代码仅用于理解行为，本工具独立运行。
